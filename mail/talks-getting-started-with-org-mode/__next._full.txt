<h2>引言</h2>
<p>我是 Harry Schwarz，thoughtbot 的一名开发者。我非常喜欢 Emacs，并用它来做各种各样的事情。特别有一种叫做 Org mode 的模式，它基本上接管了我的生活。我用它来写文档，用它来组织日历事件，有时我用它来管理待办事项，我用它写各种文章，偶尔也写博客文章。它就是一个……一个庞大的混合体。嗯，我的意思是它是有史以来最好的东西，但它确实接管了我的生活。今天，我将通过实例和一些概念性的东西，带大家入门 Org mode。</p>
<p>首先，这里有谁在某种程度上使用 Org mode？好的，大概有一半人。太好了，这会很有趣。你们会问我一些我可能答不上来的难题。</p>
<p>我喜欢以一种比较轻松的方式进行，所以如果你有任何问题，尽管喊出来就行。</p>
<p><strong>问：</strong> 你能给我们介绍一下你现在使用的版本背景吗？</p>
<p><strong>答：</strong> 当然，我使用的版本。是的，我用的是 Emacs 24.5，并且我用的是 Org 版本 8。我相信我用的是当前的版本，是的。我不确定具体是哪个小版本，但肯定是 8 点几。我认为我接下来要演示的内容不会有很强的版本特定性。如果你使用的是过去几年内发布的任何版本，这些应该都能正常工作。</p>
<h2>Org mode 基础与标记语言</h2>
<p>Org mode 最初是作为一个大纲编辑器出现的。你可以用一个星号开始大纲中的条目。</p>

<p>Org mode 基本上是一种标记语言。如果你用过像 Markdown 之类的东西，它很像，但在上千个方面要好得多，我们稍后会深入探讨。它也类似于 reStructuredText 和所有其他类似的东西。</p>
<p>那么，我们来谈谈标记。你可以做很多不同种类的标记操作。你可以用星号使文本 <strong>加粗</strong>。你可以用斜杠使它们 <em>倾斜</em>。你可以用等号使它们 <code>等宽</code>（verbatim）。你会注意到，随着我们的操作，样式会有一点变化。如果你真的想，你也可以 <del>划掉</del> 文本，我觉得这看起来很糟糕，但没关系。</p>

<h2>文学编程 (Literate Programming)</h2>
<p>我们展示了你可以在你的 Org 文件中评估源代码块。另一个你可以做的很酷的事情是评估一个 Org 文件中所有的源代码块。我有一个非常非常简单的 <code>init.el</code> 文件。让我在这里打开它。<code>emacs/init.el</code>。它只有一行。我运行这个命令 <code>org-babel-load-file</code>，它加载了一个 Org 文档，也就是我的 <code>configuration.org</code>。它的作用是遍历这个文件，找到所有标记为 Emacs Lisp 的源代码块，并按顺序评估它们。</p>
<p>所以如果我们看一下实际的配置文件，它…我的意思是，它就是一个 Org 文档。我用了一个叫做 <code>sensible-defaults</code> 的包来设置一些东西。我在这里设置了我的个人信息。让我想想…哦，这是我的 Org 相关设置。我有一些显示偏好。哦，就是这个：<code>org-bullets-mode</code>。我把它设置成了 true。我相信你还需要安装一个叫做 <code>org-bullets</code> 的包。你也可以做一些事情，比如隐藏前导星号，就是如果你有比如三个星号，它只会显示第三个，并且会正确缩进。</p>
<p>总之，发生的事情是，有一个叫做 Babel 的系统，它与 Org 相关联，它会遍历你的文档，找到所有用适当语言编写的源代码，并从中生成一段新的源代码，一个新的文档。这就是我正在做的。</p>
<p>关于这部分有什么问题吗？这有点神奇。</p>
<p>我对文学编程有很多看法。我认为它在大多数情况下是个相当糟糕的主意。但对于像这样不怎么变化，并且有点意在教学——就是人们应该从中学习的东西——我认为这是一种非常有用的方式。而且，当我把我的配置转换成 Org mode 时，我发现了各种疯狂的重复、奇怪的不一致等等。所以这是一次非常好的练习。</p>

<p>我实际上认为文学编程几乎总是一个糟糕的主意。如果你有一个项目，我认为好的软件工程实践是关于确保该项目在未来能够轻松地进行更改。我认为，当代码更改时，大量需要同时更改的注释也会使更改变得更加困难，并最终会变得具有欺骗性，因为人们不会总是更改那些注释。等等等等。关于这个话题，我准备了一个半小时的长篇大论，如果你想听，之后可以让我释放出来。但是，是的，除了这种东西，我还没怎么用过文学编程。</p>

<h2>任务管理 (To-Do / GTD)</h2>
<p>好了，关于那些我要谈的待办事项。最初吸引我进入 Org mode 的，并非所有这些你可以做的整洁的发布功能，而是待办事项管理。我读了《搞定》（Getting Things Done），那是一本关于将你所有生活都放入待办列表的花哨的书。我想，是的，我想那么做。但我也喜欢纯文本，并且我喜欢这个来自 70 年代的笨重的老编辑器。我该如何将我所有的热情结合在一起呢？</p>
<p>事实证明，Org 非常适合这个。如果你有一些项目符号项，并且你在它前面加上单词 <code>TODO</code>，你会注意到它变成了奇怪的颜色。TODO，让我想想…“解释待办列表”。如果我按 <code>Shift+Meta+Enter</code>（Shift+Alt+Enter），它会在下面创建另一个同级条目。</p>
<p>你可以做的一件事是，你可以循环切换状态。如果我有这个家伙在这里，我可以按 <code>Ctrl+C Ctrl+T</code>，它就会被标记为 <code>DONE</code>（完成）。多么高级！我可以再按一次 <code>Ctrl+C Ctrl+T</code>，它会移除 TODO 标记。如果我再按一次 <code>Ctrl+C Ctrl+T</code>，它会循环回到 <code>TODO</code>。如果我愿意，我可以更改该文件的一些元数据，来说明我想要在那个循环中插入额外的状态，甚至可以有多个循环。就我个人而言，我使用 <code>TODO</code>、<code>WAITING</code> 和 <code>DONE</code>。<code>WAITING</code> 用于那些我被阻塞、等待别人的事情。所以，这都很酷。</p>
<p>请注意，当我这样做时（标记为 DONE），它在末尾添加了这个小时间戳，这相当高级。顺便说一句，关于 Org 时间戳的一个很酷的事情是，你可以用 <code>Shift+左/右</code> 来修改它们。所以我可以像是，“哦，让我们换到另一天”。这挺酷的。</p>
<p>我可以给事情附加截止日期（deadlines）。假设我今天真的需要解释待办列表。我可以按 <code>Ctrl+C Ctrl+D</code>，这会在我的文本编辑器里调出这个神奇的日历，这太疯狂了。它会让我选择一天。假设我早该完成那个了。现在这个被分配了一个截止日期。我可以用 <code>Shift+左/右</code> 来切换日期，用 <code>Shift+上/下</code> 按月份切换，如果我愿意的话。我觉得这很酷。</p>
<p><strong>问：</strong> 你能按截止日期排序吗？我能做到吗？</p>
<p><strong>答：</strong> 哦天哪，哦天哪。如果我按 <code>Ctrl+C a</code>，它会召唤出 Agenda（议程）。这也是一个我放大不了的东西，该死。然而，这里有一个字母列表以及它们的作用。在这些功能中，我可以看到当前周或天的议程，一个包含我所有待办事项条目的列表——如果我配置了，可以跨多个文件。你需要写一点点 elisp 来设置这些，但这相当直接。我可以基于特定的标签进行搜索。有标签功能。嗯…我可以做各种疯狂的事情。所以，是的，我完全可以按东西排序。</p>
<p>但我实际做的，然而，是当我完成某件事时，我按 <code>Ctrl+C Ctrl+X Ctrl+A</code>（或 <code>Ctrl+C $</code>）来归档它。它的作用是，它拿到那个条目，将它标记为完成，设置那个 <code>CLOSED:</code> 时间戳，将它从当前所在的文件中移除，并将其附加到我别处的一个 <code>archive.org</code> 文件的末尾。所以我有一个列表，记录了我在过去五年里做过的所有事情，这挺不错的，还有我做它们的时间，所有这些好东西。所以在实践中，我不需要按“完成”来排序，因为它们已经被“完成”排序了——我有了这个（指归档文件）。</p>
<p><strong>问：</strong> 这个问题跟 Org mode 或 Emacs 关系不大，但是作为一个可能读 Jeff Atwood 博客的人…</p>
<p><strong>答：</strong> 哦是的。</p>
<p><strong>问：</strong> 你看到他…我怀疑你看到了他大概六个月前关于待办列表的长篇大论…</p>
<p><strong>答：</strong> Jeff Atwood 关于待办列表的长篇大论？那篇文章的论点是什么？</p>
<p><strong>问：</strong> 是说你应该把它们都扔掉。扔掉你所有的包、约定，等等，然后就每天做三件事。因为你能记住事情，这很简单，你不需要写下来，你不需要把它放进 Emacs，你不需要跟踪它，你会知道你是否完成了它们。</p>
<p><strong>答：</strong> 酷。</p>
<p><strong>问：</strong> 我看到了那个，而且我做过这么多这方面的事情，有这么多历史，可能至少可以追溯到 1992 年。我看到那个之后，对于工作来说，我立刻就信了。当然。但我很好奇你是否遇到过它，以及你的反应会是什么？</p>
<p><strong>答：</strong> 现在你提到了，我听说过。录音提示：那是 Jeff Atwood 关于扔掉你的待办列表，每天只写下你需要做的三件最重要的事情的帖子。我的回应是：Jeff Atwood 怎么会记得他什么时候需要去看牙医？如果我没有东西告诉我，我永远不会记得。对我来说那是日历条目，但是，我有远不止三件事情需要做，而且它们大多是我不想记住的事情。所以我真的需要某种积压列表（backlog）。</p>
<p>我觉得，如果你把所有事情都放在一个待办列表里，并且你非常勤奋地维护它，从中移除事情，并在有新需要做的事情进来时追加到里面，那会工作得相当好。如果你只是半途而废，有一个待办列表，里面的东西你不定期更新，它就那么笼罩着你，与你脑子里一个未写下的、让你担忧的事情列表同时存在，那么你会过得很糟糕，而且它不会起作用。根据我的经验，是这样的。所以我认为，“没有待办列表”是一个选项。我认为那样很难跟踪事情，因为我有超过三件事情需要做，而且其中一些我明天就需要做。</p>
<p><strong>问：</strong> 这也基于一个前提，就是你并不一定想记住你做过什么。</p>
<p><strong>答：</strong> 是的，那也是。我在这里的做法是，我现在有了我做过的所有事情的记录。这有时候挺方便的。我偶尔需要知道，“我什么时候付了那张账单？”或者，你知道，“我上次去看牙医是什么时候？”之类的，我可以很容易地查到。这有点用。是的。所以如果你喜欢那样，我认为这是一种很好的做事方式。如果你有不同的系统，尽管不用这个。</p>
<p>我偶尔会为工作建立一个这样的小列表。你知道，比如我知道我今天有四五件小事要做，我就会建一个单独的小列表，这只是帮助我记住它们。或者有时候我直接在纸上做。</p>
<p>我没有展示日程安排（schedule）。我没有。让我给你看看议程。哦天哪，我希望我的生活中没有什么尴尬的事情正在发生。不，还好。不多。这会发布到互联网上。我正在写一些…该死的…代码示例。我有一个绩效评估需要填写。让我想想…我需要读一本关于 Haskell 的书，这对我来说很重要。其中一件事我有一个截止日期。所以这就是…这就是我接下来一周的总结。我不太常用日期相关的功能。我大部分的日程安排使用更传统的日历，但有些人非常喜欢这样做。</p>
<p><strong>问：</strong> 我使用 Org mode 的问题之一是，你知道，我捕捉了成堆成堆成堆的待办事项，但我总是给它们分配一个截止日期，但实际上搜索那些没有截止日期的待办事项我发现有点棘手。所以我不知道…</p>
<p><strong>答：</strong> 是的。</p>
<p><strong>问：</strong> 所以我希望所有事情都有一个应该完成的日期，你知道，只是为了它最终能出现。</p>
<p><strong>答：</strong> 是的。所以，问题是，没有截止日期的事情怎么完成，有点这个意思。</p>
<p><strong>问：</strong> 确切地说。</p>
<p><strong>答：</strong> 哎，我人生的写照。嗯…所以我只给那些有非常确定完成时间的事情分配截止日期。比如，你知道，我真的应该读那本 Haskell 书，但那没有截止日期。我可以说我需要在周六之前完成那一章。但我并不需要在周六之前完成。既然那是一个编造的截止日期，那会让我不尊重任何截止日期，最终事情就会从缝隙中溜走。所以我倾向于不那样做。</p>
<p>因为 Org 是层级化的，我的意思是，我可以把待办事项嵌套在其他待办事项里。所以我可以说，“哦，你知道，我有所有这些事情…”因为我可以嵌套待办事项，我可以创建项目，它们会有一系列我可以划掉的任务。所以我认为每隔一段时间，过一遍你的待办列表，稍微“整理”（grooming）一下，只是为了用一种合理的方式组织事情，是非常有用的。所以我倾向于经常这样做。我的意思是，不是非常频繁，但你知道，每隔几天我会看看，“这里到底发生了什么？”然后清理一下，用更合理的方式组织一下。这通常能让事情得以完成。</p>
<p>不必在这里再次完全 GTD 化，关于《搞定》的哲学，但是，对于每个项目，有一个“下一步行动”（Next Step）任务是非常有用的。我发现这种方式对此非常有利。是的。</p>

<p><strong>Org mode 基础与标记语言</strong></p>
<ul>
<li><strong>大纲结构 (Outliner)</strong>
<ul>
<li>Org mode 最初是一个大纲编辑器。</li>
<li>使用星号 (<code>*</code>) 创建层级标题 (一个 <code>*</code> 为一级，两个 <code>**</code> 为二级，以此类推)。</li>
<li>标题下可添加任意文本块。</li>
<li>可使用 <code>Tab</code> 键方便地折叠和展开各级标题下的内容。</li>
<li><code>Meta+Enter</code> (Alt+Enter) 可快速创建同级标题。</li>
<li><code>Meta+Up/Down</code> (Alt+Up/Down) 可调整标题及其内容的顺序。</li>
</ul>
</li>
<li><strong>标记语法 (Markup)</strong>
<ul>
<li>Org mode 是一种标记语言，类似 Markdown、reStructuredText，但功能更强大。</li>
<li>文本格式化：
<ul>
<li><code>*粗体*</code></li>
<li><code>/斜体/</code></li>
<li><code>_下划线_</code> (视频中未明确演示，但为标准语法)</li>
<li>=等宽代码=(verbatim)</li>
<li><code>+删除线+</code></li>
</ul>
</li>
<li>列表：
<ul>
<li>使用 <code>-</code>, <code>+</code> 或 <code>*</code> (在非标题行首) 创建无序列表。</li>
<li>使用 <code>1.</code> 或 <code>1)</code> 创建有序列表。</li>
</ul>
</li>
<li>链接：
<ul>
<li>使用 <code>C-c C-l</code> (Ctrl+C Ctrl+L) 插入链接。</li>
<li>格式：<code>[[链接地址][显示文本]]</code>。</li>
<li>支持多种链接类型：
<ul>
<li>网页链接 (e.g., <code>[[http://orgmode.org][Org mode 官网]]</code>)</li>
<li>本地文件链接 (e.g., <code>[[file:path/to/your/file.org::*可选标题或行号][文件描述]]</code>)，非常适合项目内跳转或引用。</li>
<li>邮件链接 (需配置邮件客户端)。</li>
<li>待办事项链接。</li>
</ul>
</li>
<li>使用 <code>C-c C-o</code> (Ctrl+C Ctrl+O) 打开光标处的链接。</li>
</ul>
</li>
</ul>
</li>
</ul>
<p><strong>表格处理</strong></p>
<ul>
<li>Org mode 的表格功能远胜于 Markdown。</li>
<li>创建表格：
<ul>
<li>输入 <code>|</code> 开始一行，然后输入表头或内容，用 <code>|</code> 分隔。</li>
<li>按 <code>Tab</code> 或 <code>Enter</code> 键，Org mode 会自动对齐表格。</li>
<li>输入 <code>|-</code> 后按 <code>Tab</code> 可快速生成分隔线。</li>
</ul>
</li>
<li>编辑与导航：
<ul>
<li><code>Tab</code> 键在单元格间移动。</li>
<li><code>Enter</code> 键移动到下一行。</li>
</ul>
</li>
<li>行列操作：
<ul>
<li><code>Meta+方向键</code> (Alt+方向键) 可快速移动行或列，重排表格结构。</li>
</ul>
</li>
<li>高级功能 (提及但未深入)：
<ul>
<li>表格内支持公式计算，使其成为一个简单的电子表格。</li>
<li>可以嵌入 Emacs Lisp 代码进行复杂计算。</li>
<li>支持丰富的格式化选项。</li>
</ul>
</li>
</ul>
<p><strong>导出功能</strong></p>
<ul>
<li>强大的导出能力是 Org mode 的核心优势之一。</li>
<li><code>C-c C-e</code> (Ctrl+C Ctrl+E) 打开导出调度器 (Export Dispatcher)。</li>
<li>支持导出为多种格式：
<ul>
<li>HTML</li>
<li>LaTeX (进而生成 PDF，效果精美)</li>
<li>Markdown (包括 GFM - GitHub Flavored Markdown，需 <code>ox-gfm</code> 包)</li>
<li>纯文本 (Plain Text)</li>
<li>iCalendar (用于日历事件)</li>
<li>Beamer (基于 LaTeX 的演示文稿，需 <code>ox-beamer</code> 包)</li>
<li>Twitter Bootstrap 样式的 HTML (需 <code>ox-twbs</code> 包)</li>
<li>以及更多其他格式，可通过扩展添加。</li>
</ul>
</li>
<li>导出范围：
<ul>
<li>可导出整个缓冲区 (Buffer)。</li>
<li>可仅导出当前子树 (Subtree)。</li>
<li>可在导出菜单 (<code>C-c C-e</code>) 后按 <code>Ctrl+s</code> 切换导出范围。</li>
</ul>
</li>
<li>非常适合撰写学术论文 (利用 LaTeX 的排版优势，但使用更友好的 Org 语法)。</li>
</ul>
<p><strong>元数据与文档选项</strong></p>
<ul>
<li>使用 <code>#+KEY: VALUE</code> 格式在文件开头定义元数据和选项。</li>
<li>常用元数据：
<ul>
<li><code>#+TITLE: 文档标题</code></li>
<li><code>#+AUTHOR: 作者名</code></li>
<li><code>#+DATE: 日期</code></li>
</ul>
</li>
<li>常用选项 (<code>#+OPTIONS</code>)：
<ul>
<li><code>toc:nil</code> 或 <code>toc:t</code> 控制是否生成目录 (Table of Contents)。</li>
<li><code>num:nil</code> 或 <code>num:t</code> 控制章节是否自动编号。</li>
<li>还有许多其他选项用于控制导出时的各种行为和外观。</li>
</ul>
</li>
</ul>
<p><strong>代码块处理 (Babel)</strong></p>
<ul>
<li><strong>插入与编辑代码块</strong>
<ul>
<li>使用 <code>#+BEGIN_SRC &#x3C;language> ... #+END_SRC</code> 结构包裹代码。</li>
<li>快捷方式：输入 <code>&#x3C;s</code> 后按 <code>Tab</code> 可快速插入代码块结构。</li>
<li><code>&#x3C;language></code> 指定代码块的语言 (e.g., <code>ruby</code>, <code>python</code>, <code>emacs-lisp</code>, <code>shell</code>)。</li>
<li><code>C-c '</code> (Ctrl+C 单引号) 可在对应语言的主模式 (Major Mode) 下编辑当前代码块，提供语法高亮、补全等支持。</li>
</ul>
</li>
<li><strong>代码块导出</strong>
<ul>
<li>导出时，代码块通常会进行语法高亮 (可配置，演讲者提到使用 <code>minted</code> 包获得更好看的 LaTeX 输出)。</li>
</ul>
</li>
<li><strong>代码执行 (Literate Programming 核心)</strong>
<ul>
<li><code>C-c C-c</code> (Ctrl+C Ctrl+C) 在代码块内可执行该代码块。</li>
<li>执行结果可以：
<ul>
<li>直接插入到 Org 文档中 (在代码块下方生成 <code>#+RESULTS:</code> 块)。</li>
<li>被后续的代码块作为输入使用 (通过设置代码块头参数 <code>:var</code> 等)。</li>
<li>用于生成图表 (e.g., 将数据传递给 <code>gnuplot</code> 代码块)。</li>
</ul>
</li>
<li>演示了执行 Ruby 阶乘函数并计算 <code>$factorial(5)$</code>。</li>
</ul>
</li>
</ul>
<p><strong>数学与公式</strong></p>
<ul>
<li>Org mode 内建对 LaTeX 数学语法的支持。</li>
<li>特殊字符：可以直接输入 LaTeX 命令，如 <code>\alpha</code>, <code>\beta</code>, <code>\sum</code> 等，Org mode 会尝试实时预览或在导出时正确处理 ($\alpha$, $\beta$, $\sum$)。</li>
<li>行内公式：使用 <code>$...$</code> 包裹 LaTeX 公式，例如 <code>$E=mc^2$</code>。</li>
<li>块级公式：
<ul>
<li>使用 <code>$$...$$</code> 包裹单行居中公式。</li>
<li>使用 <code>\begin{equation} ... \end{equation}</code> 或 <code>\begin{align*} ... \end{align*}</code> 等标准 LaTeX 环境书写多行或对齐的公式。</li>
</ul>
</li>
<li>导出处理：
<ul>
<li>导出为 HTML 时，通常使用 MathJax 库在浏览器端渲染 LaTeX 公式。</li>
<li>导出为 PDF (通过 LaTeX) 时，公式由 LaTeX 原生处理。</li>
</ul>
</li>
</ul>
<p><strong>文学编程 (Literate Programming)</strong></p>
<ul>
<li>Babel 功能使得 Org mode 成为优秀的文学编程工具。</li>
<li>核心思想：将代码、代码的说明文档、执行结果有机地组织在同一个 Org 文件中。</li>
<li>演讲者案例：其 Emacs 配置文件 (<code>init.el</code>) 极简，只包含一行 <code>(org-babel-load-file "path/to/configuration.org")</code>。</li>
<li>实际的配置逻辑和说明都在 <code>configuration.org</code> 文件中，通过带有 <code>:tangle yes</code> (视频未明确提，但这是标准做法) 或直接执行的方式生效。</li>
<li>优点：
<ul>
<li>配置文档化、易于理解和维护。</li>
<li>适合教程、报告、可复现研究等场景。</li>
</ul>
</li>
<li>观点：文学编程不一定适用于所有软件开发场景 (特别是快速迭代的项目，维护成本可能较高)，但非常适合配置文件、书籍、论文等相对稳定或以教学为目的的内容。</li>
</ul>
<p><strong>任务管理 (To-Do / GTD)</strong></p>
<ul>
<li>Org mode 是强大的个人任务管理系统，支持 GTD (Getting Things Done) 方法论。</li>
<li><strong>创建与标记任务</strong>
<ul>
<li>在标题前加上 <code>TODO</code> 关键字即可将其标记为待办任务 (关键字可自定义)。</li>
<li><code>Shift+Meta+Enter</code> (Shift+Alt+Enter) 可快速创建新的同级 TODO 项。</li>
</ul>
</li>
<li><strong>任务状态切换</strong>
<ul>
<li><code>C-c C-t</code> (Ctrl+C Ctrl+T) 可按预设流程循环切换任务状态 (e.g., <code>TODO</code> -> <code>DONE</code> -> 无状态)。</li>
<li>可以自定义状态关键字和转换流程 (e.g., 添加 <code>WAITING</code>, <code>CANCELLED</code> 等状态)。</li>
<li>任务完成 (切换到 <code>DONE</code> 状态) 时，会自动添加 <code>CLOSED:</code> 时间戳。</li>
</ul>
</li>
<li><strong>时间管理</strong>
<ul>
<li><code>C-c C-d</code> (Ctrl+C Ctrl+D) 为任务设置截止日期 (Deadline)，会弹出日历供选择。</li>
<li><code>C-c C-s</code> (Ctrl+C Ctrl+S) 为任务设置计划开始日期 (Scheduled)。</li>
<li><code>Shift+方向键</code> 可在日期上快速调整年/月/日。</li>
</ul>
</li>
<li><strong>Agenda 视图</strong>
<ul>
<li><code>C-c a</code> (Ctrl+C a) 打开强大的 Agenda 视图。</li>
<li>可以聚合来自多个 Org 文件的任务和日程信息。</li>
<li>提供日视图、周视图、全局 TODO 列表、按标签/优先级/类别过滤等多种视图。</li>
<li>显示即将到期或已过期的任务。</li>
</ul>
</li>
<li><strong>归档 (Archiving)</strong>
<ul>
<li><code>C-c C-x C-a</code> (或 <code>C-c $</code>) 将已完成的任务移动到指定的归档文件中 (通常是同目录下或指定路径下的 <code>*.org_archive</code> 文件)。</li>
<li>保持主 Org 文件整洁，同时保留完整的任务历史记录。</li>
</ul>
</li>
<li><strong>任务管理哲学讨论</strong>
<ul>
<li>回应 Jeff Atwood 的 "每天只做三件事" 观点：演讲者认为对于需要长期跟踪或有明确时间点的事情 (如看牙医)，任务列表和提醒是必要的。</li>
<li>强调仅对“硬性”截止日期使用 Deadline，避免虚假 Deadline 降低其约束力。</li>
<li>提倡通过层级结构组织项目、定期“梳理”(grooming) 任务列表、明确“下一步行动”(next action) 来管理任务。</li>
</ul>
</li>
</ul>
<p><strong>高级功能与扩展</strong></p>
<ul>
<li><strong>Org Capture</strong>
<ul>
<li><code>C-c c</code> (Ctrl+C c) 触发 Capture 功能。</li>
<li>允许通过预设模板快速捕捉笔记、任务、想法等，并自动存入指定 Org 文件的预定位置。</li>
<li>演讲者绑定了 <code>Meta+n</code> (Alt+n) 作为快捷键。</li>
</ul>
</li>
<li><strong>Org Publish</strong>
<ul>
<li>用于将一系列 Org 文件组成的“项目”发布为网站、文档集等。</li>
<li>可以定义项目结构、应用模板、处理链接和资源文件。</li>
<li>演讲者正在考虑用其替代 Jekyll 来构建个人博客。</li>
</ul>
</li>
<li><strong><code>org-drill</code></strong>
<ul>
<li>一个基于 Org 文件内容的间隔重复学习 (Spaced Repetition) / 抽认卡 (Flashcard) 工具。</li>
</ul>
</li>
<li><strong>移动端支持</strong>
<ul>
<li><code>org-mobile</code> (官方，早期体验不佳)。</li>
<li><code>Orgzly</code> (Android 应用，社区推荐，功能较完善)。</li>
<li><code>Drafts</code> (iOS 应用，可通过动作将文本处理后发送到 Org 文件，适合快速捕捉)。</li>
</ul>
</li>
</ul>
<p><strong>同步与外部工具</strong></p>
<ul>
<li><strong>同步方案</strong>
<ul>
<li>演讲者使用 <code>ownCloud</code> (一个开源、自托管的云存储和协作平台) 在电脑和可能存在的移动设备间同步包含 Org 文件的目录。</li>
</ul>
</li>
<li><strong>ownCloud 简介</strong>
<ul>
<li>提供类似 Dropbox 的文件同步功能。</li>
<li>提供日历 (CalDAV) 和联系人 (CardDAV) 服务。</li>
<li>演讲者用它替代 Google Calendar 等服务。</li>
<li>可在自己的服务器上部署，掌控数据。</li>
</ul>
</li>
<li><strong>版本控制</strong>
<ul>
<li>目前演讲者未对其 Org 文件直接使用 Git 等版本控制系统进行管理，但有考虑过。</li>
</ul>
</li>
</ul>
<p><strong>总结</strong></p>
<ul>
<li>Org mode 是一个极其强大和灵活的 Emacs 模式，集大纲编辑、标记语言、任务管理、文学编程、导出发布等多种功能于一身。</li>
<li>虽然初看起来可能复杂，但其纯文本、可扩展的特性使其深受许多用户喜爱。</li>
</ul>
