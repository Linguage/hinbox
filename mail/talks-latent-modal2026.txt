<h2>访谈正文</h2>
<h2>引言：Modal、C 轮融资与艺术派对</h2>
<p><strong>Swyx:</strong> 我们请到了 Modal 的 CTO Akshat，以及 Vibhu。恭喜你们完成 C 轮融资。</p>
<p><strong>Akshat:</strong> 谢谢。</p>
<p><strong>Swyx:</strong> 你们昨天的派对太棒了。</p>
<p><strong>Akshat:</strong> 是啊。</p>
<p><strong>Swyx:</strong> 从所有照片和所有周边来看。</p>
<p><strong>Akshat:</strong> 我们搞了一堆艺术装置，挺有意思的，看到我们的产品摆在展台上，旁边就是罗丹的作品。</p>
<p><strong>Swyx:</strong> 非常好。非常好。你们起步的时候，并不是一家 GPU 推理公司。也许在你心里是。带我们回到最初的故事吧。</p>
<h2>Modal 的起源：超越 Kubernetes 的新运行时</h2>
<p><strong>Akshat:</strong> 我最初是通过一位投资人认识 Eric 的，他是 CEO。那时候 Eric 已经在考虑构建一个新的运行时，他思考的出发点是：为什么工作流编排产品这么难用？因为你必须把它们跑在 Kubernetes 上。Kubernetes 很难管理。它不是为突发性和自定义镜像而生的，</p>
<p><strong>Swyx:</strong> 是啊</p>
<p><strong>Akshat:</strong> 它的开发者体验很糟糕。</p>
<p><strong>Swyx:</strong> 我，我插一句</p>
<p><strong>Akshat:</strong> 好</p>
<p><strong>Swyx:</strong> 给新来的听众说一下，我们两年前采访过 Eric，那里有更多关于 Spotify 等等的故事。</p>
<p><strong>Swyx:</strong> 我是在 Data Council 上遇到 Eric 的，因为他做了那个关于无服务器容器栈的演讲，就是你们做的那套，那是我第一次觉得，“好吧，我得非常认真地对待 Modal”的时刻。</p>
<p><strong>Akshat:</strong> 是啊。</p>
<p><strong>Swyx:</strong> 但当时还是很不清楚，比如，我仅仅为了我的数据管道就需要这一切吗？</p>
<p><strong>Akshat:</strong> 是的。最初我们想的是，如果我们构建一个更好的运行时，它本身就是一个非常有用的原语。有很多东西可以通过无服务器函数来解决，比如你可以做 ETL 的事情，你可以做任务队列，你可以做所有这些突发性处理，结果发现每家公司都有这种需求。但当时我们也在想，这是一个原语，我们可以在此基础上构建一整套产品，而且是非常垂直化的。所以也许数据工程会是第一个，但我们当时在考虑推理。那时候更多是经典推理，比如计算机视觉的东西、跑 XGBoost 之类的。但我们在 ChatGPT 发布前一年就把 GPU 加进了产品里。</p>
<h2>从无服务器容器到 GPU 工作负载</h2>
<p><strong>Swyx:</strong> 不错。</p>
<p><strong>Akshat:</strong> 我们只是没想到它会那么重要。</p>
<p><strong>Swyx:</strong> 是啊，就像加个 A100 而已。</p>
<p><strong>Vibhu:</strong> 有没有什么早期的关键问题，真正激发了你们去构建它？</p>
<p><strong>Akshat:</strong> 有。主要是，当时市面上的工具没有一个是为一流的开发者体验而构建的，而且我们看到的一个普遍趋势是，很多工作负载都非常……我希望有个更好的词，但就是计算密集型。比如，它们需要多得多的资源，所以你需要大量地扩缩容，而 Kubernetes 是为慢速扩缩容设计的，更多是为 Web 服务器用例。而且这些工作负载运行的环境也变得更加专业化。比如，有时候它们需要加速器，有时候它们需要不同种类的镜像，这是我们在很多公司都看到的一贯现象。那会是下一步。</p>
<h2>软件定义基础设施与基于装饰器的开发者体验</h2>
<p><strong>Swyx:</strong> 是啊。是啊。说得好。我不知道这在早期故事里占多大比重，但我在 Temporal 的时候写过一篇关于基础设施的文章，软件定义基础设施之类的。</p>
<p><strong>Akshat:</strong> 对，自供给</p>
<p><strong>Swyx:</strong> 自供给。</p>
<p><strong>Akshat:</strong> 对。</p>
<p><strong>Swyx:</strong> 是啊。我自己写的文章我都记不清了。</p>
<p><strong>Swyx:</strong> 然后你把我放到了落地页上。</p>
<p><strong>Akshat:</strong> 对。我们真的很喜欢这个说法，所以就偷过来了。</p>
<p><strong>Swyx:</strong> 因为你们有一个洞察，就是一切都可以放在装饰器里，和代码放在一起，对吧？</p>
<p><strong>Akshat:</strong> 对。</p>
<p><strong>Swyx:</strong> 这是最初故事的一大部分吗</p>
<p><strong>Akshat:</strong> 是的</p>
<p><strong>Swyx:</strong> 还是说只是一个开发者体验层？</p>
<p><strong>Akshat:</strong> 那真的非常重要，因为我们真的不想让人们花那么多时间写 YAML，而且看起来你确实可以大幅压缩你所做的事情的表面积，把它放进代码里，这样你就可以像操作其他代码一样操作它，构建更具表现力和动态性的东西。所以是的，这一直是非常重要的一部分。</p>
<p><strong>Swyx:</strong> 然后反对的声音就是，这是一种 DSL。</p>
<p><strong>Akshat:</strong> 对。</p>
<p><strong>Swyx:</strong> 你们是闭源的。我被锁定在 Modal 上了。</p>
<p><strong>Akshat:</strong> 对。我们其实从来没有因此受到反对，因为 Modal 的好处是你可以带上你已有的任何代码，当然，DSL 是在配置层，用于你用什么硬件、如何扩缩容，但代码仍然是你的。</p>
<p><strong>Akshat:</strong> 这一直是我们故事的重要部分，即使现在我们做推理也是如此。</p>
<p><strong>Swyx:</strong> 是啊。</p>
<p><strong>Vibhu:</strong> 你觉得今天还有多少保持不变？比如如果你今天要构建某个东西，开发者体验非常重要，但我觉得，很多东西已经变了，只要把它接到一个智能体上，让 Claude Code、让 Codex 来实现一个工具。有一些智能体原生的原语，和我自己做这件事是不一样的，对吧？</p>
<h2>开发者体验 → 智能体体验</h2>
<p><strong>Akshat:</strong> 我们已经把 SDK 团队的思路从开发者体验改成了智能体体验，我们认为适用于 DX 的同样的好处也适用于 AX，也就是说，为什么要让一个智能体去读几百个 Kubernetes 文件，写甚至没有类型的 YAML，而它只需要在装饰器里做几处修改，就能获得这个自供给的运行时，能够实时看到它的改动生效？是的，从我们交流的客户来看，他们发现 Modal 对智能体来说比在另一种基底上操作要快得多。</p>
<p><strong>Swyx:</strong> 是啊，因为就像你说的，你把基础设施需求和运行它的代码放在一起。</p>
<p><strong>Akshat:</strong> 对。</p>
<p><strong>Swyx:</strong> 那么现在的反面论点是，没人再看自己的代码了，所以这没意义。</p>
<p><strong>Akshat:</strong> 是啊，人们不看代码了。但我们仍然看到一件非常重要的事，就是可观测性。</p>
<p><strong>Swyx:</strong> 是啊。</p>
<p><strong>Akshat:</strong> 比如你的仪表盘有多好？当然，我们把很多都推到了 CLI 上，这样智能体可以自己做调查，但你仍然需要人类去解读正在发生什么，做判断之类的。我觉得，这可能比看代码本身更重要。</p>
<p><strong>Swyx:</strong> 是的，因为你可以试着把代码当作黑盒，然后看它产生的可观测行为，然后直接提示一个改动。</p>
<h2>Modal 是做什么的：AI 云原语</h2>
<p><strong>Akshat:</strong> 对。</p>
<p><strong>Swyx:</strong> 所以我觉得不专门化是需要一点克制的，不说“我想发布一个新原语”，然后就保持通用。</p>
<p><strong>Swyx:</strong> 人们问你，“你们是做什么的？”你说，“我不知道。我们能做这个，也能做那个。”</p>
<p><strong>Vibhu:</strong> 我很好奇，好吧，如果我们问你，即使在高层次上，Modal 是做什么的？你们做的事情很多，沙箱、GPU、所有东西。你怎么回答？</p>
<p><strong>Akshat:</strong> Modal 是一个云平台，我们从头构建了面向 AI 应用的原语。目前它覆盖推理、训练、批处理和沙箱工作负载。</p>
<p><strong>Akshat:</strong> 但我们还在构建更多</p>
<p><strong>Swyx:</strong> 我注意到你没说 Web 服务器，所以像那种常开的大规模 Kubernetes 类型的东西仍然有它的角色。</p>
<p><strong>Akshat:</strong> 是的，绝对。我们不是想和那些渲染类的公司竞争，因为我们认为我们的差异化在于那些需要专门计算、需要大量扩缩容的工作负载。是的，它们的形态就是不一样。</p>
<h2>与前沿初创公司并肩工作</h2>
