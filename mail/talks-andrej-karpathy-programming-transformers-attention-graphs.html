摘要

这组演讲与课堂讲解连接了大语言模型的应用方式与底层结构。Karpathy 先用数据引擎、链式思考、虚拟终端、智能家居和语言模型后端，说明编程如何从设计算法、设计数据集走向设计提示词；随后回顾神经网络与注意力机制的发展，将 Transformer 拆解成有向图上的通信和节点内部的计算，并结合 nanoGPT 讲解 token 编码、因果掩码、交叉熵训练及自回归生成。他最终强调，Transformer 的价值不仅在表达能力，还在可优化性和硬件效率：三者共同使它成为一种可通过提示词重新配置的通用文本计算机。

内容概述

  • 软件范式的三次变化： 从手写算法，到用数据集训练神经网络，再到通过自然语言提示词配置大语言模型。
  • 提示词如何驱动任务： 逐步推理、模拟 Linux 终端、控制智能家居、充当应用后端，以及系统提示词对行为的塑造。
  • 统一架构与注意力的历史： 从手工特征、序列到序列模型和编码器瓶颈，到软注意力及 Transformer 在多种模态中的应用。
  • 有向图上的消息传递： 通过查询、键和值理解自注意力、交叉注意力、多头并行，以及编码器与解码器的连接约束。
  • nanoGPT 实现与通用计算机视角： 沿着数据批次、嵌入、残差块、因果掩码和文本生成梳理实现，再讨论表达能力、可优化性及 GPU 效率。

从斯坦福到 OpenAI：我为什么喜欢动手做东西

大约七年前，我还在这里，在斯坦福读博士。后来去了 OpenAI，再后来去了特斯拉，而就在一周前，我又回到了 OpenAI。

所以，我现在刚刚开始重新熟悉 OpenAI 的工作。在斯坦福时，我研究的是早期连接图像与自然语言的神经网络。如果你们知道今天的 CLIP，那么当时的一些网络就和它有些相似；我也做过早期的图像描述生成模型。在 OpenAI，我研究过图像生成模型，以及不少强化学习方面的东西。

所以，当你们看到别人引用 ImageNet 上的人类准确率时，那个“人类”就是那一周的我。我也写过活动追踪应用，比如统计自己写了多少代码，如果连续写了一段时间，就记录一个连续编程纪录。我还追踪自己的咖啡因水平等等，挺有意思的。另一个项目 arXiv Sanity Preserver，可以根据你已经喜欢的论文，帮你找到其他可能感兴趣的论文。我也经常写博客，有几篇文章后来变得比较受欢迎。

编程范式的变化：从算法到数据

你在向计算机发出指令，告诉它应该做什么。你可能会想到写 C++ 代码，给计算机下指令；也可能会想到高德纳和他的《计算机程序设计艺术》。在过去大约七十年里，编程基本上就是这样。从大的层面看，这种方式没有变：设计一个算法，然后把指令告诉计算机。它已经带我们走了很远。正是靠着把这些指令一条条写出来，我们才做出了 Linux 这样的软件。这里展示的就是 Linux 的一张示意图。

这是一个极其复杂的软件工程项目，有许多相互配合的组成部分；图中还有用于不同部分的各种性能分析器和调试器。它让我们走了很远，但还不足以解决所有问题。面对另一些问题，比如图像识别时，我们开始看到这种范式的局限。仅仅判断一张图片里有没有猫，就非常困难。你很难手写出一个能识别图片中猫的算法，因为猫会以各种各样的形态出现。

仅靠给计算机明确的指令，你也很难做出一个下棋下得特别好的程序。仅仅这样下指令，大概也做不出自动驾驶系统。我们很可能同样无法靠把所有步骤都写给计算机，来构建通用人工智能，也就是 AGI。这还不够。我们意识到，需要一种新的计算机编程方式。我给它起了一个名字，叫“软件 2.0”。

这是一种新的编程范式，核心就是神经网络。但神经网络并不只是另一种分类器，并不是拿来和随机森林之类的方法竞争的又一个选项。

神经网络是一套新的编程技术栈，编程方式也有所不同。你通过积累数据集、不断迭代数据集来给它编程。我把这个过程称为“数据引擎”。

然后，你把数据集“编译”为一个二进制程序。这里的编译过程，就是神经网络训练；编译出来的二进制程序，就是神经网络的权重。这是最终的程序，以权重的形式写成，你无法手工把它写出来。它是在你的数据集基础上，通过优化产生的，而数据集又取决于你如何积累数据。我在特斯拉大约五年的工作，基本就是这个过程：先有一个数据集，训练神经网络，再把它部署出去，然后通过大量遥测和监控，观察这个神经网络的表现。

接着，收集更多让网络感到棘手的数据，给这些数据加上标注。一部分进入测试集，另一部分回到训练集，然后一遍又一遍地重复这个循环。这就是我说的数据引擎，也是给软件 2.0 编程的方式。我并不认为 2.0 会取代 1.0 的技术栈，更准确地说，它们是叠加起来的。如果沿用这个比喻，那么要“编译”软件 2.0，你依然需要大量的软件 1.0 代码。它是在原来的基础上再加一层。

比如，在计算机视觉发展的早期，人们以为要亲自写出视觉算法；现在，你只需要一个巨大的卷积神经网络。下棋也是一样，与其手写棋类引擎，不如把它表述为强化学习问题：赢一局得到 1 的奖励，输棋或平局得到 0，或者输棋得到 −1。把它作为强化学习问题，训练神经网络，让网络识别什么样的局面更好，以及应该采取什么行动才能获胜。

你也不再需要像图中那样搭建一整条语音识别处理流水线。你真正需要的是一个大规模神经网络，用大量数据来训练，最后得到 Whisper 这样的系统。这就是关于软件 2.0 的一个非常简短的背景介绍。

大语言模型：预测下一个词，也能执行任务

现在真正让我觉得有意思的，是过去两三年里发生的事情：我们又处在一次计算范式转变之中，又有非常有趣的变化正在发生。故事从大语言模型开始。从根本上说，它们只是试图预测序列里的下一个词。但如果你初始化一个拥有一万亿参数的模型，再用整个互联网的数据去训练它，那么在“下一个词是什么”这个看似简单的预测任务里，就会开始出现一些神奇的事情。

有了这些模型，当然就可以用它们来生成内容。

生成的方法是：预测下一个内容，再把预测结果送回模型，如此不断重复，就能生成一长段文字。比如，可以用它们写诗，这一点大家已经见过一段时间了。这里有一首例子，第三首生成的诗：“我们曾拥有的，只有太阳。如今身在阴影，一切都已改变。心灵必须停驻于那些……”很不错，对吧？这些内容就是从模型里生成出来的。只要用大量数据训练它，就能得到这样的结果。更有意思的是，我们发现，这些模型还可以用来完成任务。

这里的例子都来自 GPT-3 论文。你先提供一些上下文，也就是这篇文章，然后给它几个“问题、答案、问题、答案”的例子，最后再给一个问题。这样，你就把模型引导进了一个问答模板。

它在训练文档里，很可能见过许许多多类似的内容，因此会接下给出实际答案这个任务，把这里的答案补全。用这种方式，你就能通过提示，让它执行你感兴趣的任务。而且，这些任务可以相当复杂。只要设计出合适的提示词，它就能完成相当复杂的任务。比如这里有这样一道题：一个杂耍演员可以同时抛接 16 个球。

其中一半是高尔夫球，而高尔夫球中又有一半是蓝色的。蓝色高尔夫球一共有多少个？如果你直接让语言模型续写答案，它可能会告诉你“8 个”。这个答案是错的，但这里的问题，其实是你没有用合适的方式来提示它。

人们研究了许多不同的提示技巧。比如，在这道题里，不要让模型立刻给出答案，而是让它把问题拆成几个更容易处理的步骤。因为对于单个 token，模型能够做的“思考”是有限的，而推导出这类问题的答案，需要一定的思考过程。

当你要求它“一步一步思考”时，它就能把问题拆开，不必在每个 token 上完成太多推理。它有了更多 token，也就有了更多思考的时间，答对的概率便会提高。具体来说，“让我们一步一步思考”这句提示，把这里的准确率从 17% 一下提高到了 78.7%。更有意思的是，还有效果更好的提示。后来人们发现，这样说会更好：“让我们一步一步地解决这个问题，确保得到正确答案。”

这在相关基准测试上又进一步提升了成绩，达到了 82%。

这很有意思：光是一步一步做还不够，得到正确答案也很重要。你明确表示想得到正确答案，就更有可能得到正确答案。你可以想象，在训练集中，有很多不同的分步解答，但并不是每个都能得出正确结论。通过这样的提示，你相当于进一步把模型限定在“要得出正确答案”的那一类内容上。再举一个例子。

你可以问 ChatGPT 或类似系统：“为什么会下雨？”它会给出解释，但实际上，它是在模仿互联网上能找到的平均水平的回答。可以这样想：有很多不同智力水平的人在解释为什么会下雨。如果你进一步限定：“我想听一个智商 200 的人的解释。”你就可能得到比原来更好的回答。［笑声］

这就很有意思，因为你必须记住：它是一个在整个互联网上训练出来的下一个词预测器。你需要把范围缩小，明确希望它在什么样的内容分布里进行预测。否则，它就只会模仿平均情况，而这未必是你想要的。所以，提示工程、提示词设计，确实能发挥很大的作用。

把 GPT 当作模拟器

还有一篇我很喜欢的文章。准确说，不是论文，而是一篇博客，叫《在 ChatGPT 里构建一台虚拟机》。它再次提示我们：GPT 很像一个模拟器，你可以把它引导到任意设定的世界里，得到很有趣的输出。比如，你可以要求 GPT 扮演 Linux 终端。这时你就在给它编程，告诉它应该怎样表现：“我会输入命令，你要回复终端应该显示的内容。”

“请只在一个代码块中给出终端输出，不要包含任何其他内容，不要写解释。”

你可以看到，ChatGPT 回复说，它要用 touch jokes.txt 创建一个新文件。

用文字编写智能家居与应用后端

他基本上只是用文字说明了这个智能助手的功能：“我用普通英语解释了所有这些，没有写任何程序代码。”这就像一个好得多的 Alexa，而且你可以直接用文字给它编程。他的提示词是：“请用 JSON 格式回复发给智能家居的请求，应用程序代码会解析这些回复并执行操作。你可以执行四组操作，包括命令、查询等等。”

然后，他详细说明了返回的 JSON 应该是什么样的，因为这些 JSON 会被转发给真正的家电：必须有 action 属性、location 属性、target 属性等等，也就是把数据结构描述清楚。提示词还说：“如果问题是关于你自己的，就假装自己是智能家居一个有意识的大脑、一个聪明的 AI。也请尝试帮助用户处理其他方面的问题，比如育儿、闲暇活动、心理健康。房子位于英国圣奥尔本斯，当前时间戳是……”随后，再说明这个智能家居的具体情况，告诉 GPT 家里有哪些设备、分别位于什么地方。

比如：“我家有厨房，有客厅，这个房间里有一个灯开关。”诸如此类。这样把系统设定好之后，就可以开始使用它，向它提出请求。你可以用英语说：“我让儿子上床后再读 20 分钟书。到睡觉时间，你能把这个房间的灯关掉吗？”GPT-3 就会按要求返回一个 JSON 对象。

这个 JSON 对象的类型是 command，也就是命令。

GPT-3 理解到，你大概是想在 20 分钟之后关灯，所以它给出的是“卧室，灯，关闭”，并把时间戳设置为当前时间再加 20 分钟。这样的结果直接就出来了，你可以把它发给智能设备。你也可以说：“我要出去散步，能推荐几个值得看看的地方吗？”这个智能助手知道用户住在哪里，因为提示词里有这条信息，于是它就能生成正确的 JSON，给出回答。我们只用一段文字，就编写出了一个智能助手。

这真的很不可思议。

沿着这个方向，还有一个很有意思的项目，叫“后端只需要 GPT”。

这是最近 Scale 举办的一次黑客松里获得第一名的项目，我也担任了那次比赛的评委。有趣的是，一个应用通常有前端和后端。在后端，你一般会为不同的路由写 Python 代码：收到某种请求、执行某条路由时，代码负责修改应用状态，然后生成响应。但这个项目的后端没有这些代码，没有 Python 代码。

整个后端就是一个大语言模型。它接收 JSON 格式的状态，再接收你想执行的路由，然后修改状态、以 JSON 形式输出新的状态，并把响应返回给前端。他们用这个方法做了一个待办事项应用作为例子。你可以在前端说：“删除最后两条待办事项。”把这句话发给大语言模型后，模型就会自行理解它应该是什么意思。

如果你想删掉最后两条待办事项，它就会进入 JSON，找到最后两条，把它们移除，再返回不含这两项的新 JSON，并生成响应。于是，你可以从前端用类似英语指令的方式，对数据进行各种操作。它之所以能工作，靠的就是英语。这里没有实际的 Python 后端代码，整个后端只有一个大语言模型。这是个很有意思的项目，建议你们进一步了解一下。

Transformer 如何进入不同领域

前面那两个我就先跳过，不讲了。为了让思路简单一点，也因为时间不够，我们只讲这一部分。Transformer 已经被应用到了各种不同的领域。老实说，我觉得这些应用方式有时候简直有点离谱。我以前做计算机视觉，用卷积神经网络，直觉上是说得通的。

可现在，以视觉 Transformer，也就是 ViT 为例，我们做的事情是：拿一张图片，切成一个个小方块，然后把这些小方块直接送进 Transformer，就这么简单。这有点离谱。在最简单的情况下，Transformer 甚至并不真正知道这些图像块来自什么位置，通常只是给它们加上位置编码。

因此在某种程度上，它得自己重新发现许多结构信息。我觉得这种处理方式挺奇怪的。但就是这么一个简单的基线：把大图切成小方块，把它们当作一个个独立的节点输入，效果居然相当不错。这里用的是 Transformer 编码器，所以在整个处理过程中，所有图像块都会彼此交流。图中这个例子大概有九个节点。

语音识别也是一样：拿到梅尔频谱图，把它切成一小条一小条，再送进 Transformer。有论文这么做，Whisper 也这么做。如果你看过 OpenAI 的 Whisper，就会发现，它基本上就是把 Transformer 原样搬过来：切开梅尔频谱图，送进 Transformer，再假装自己处理的是文本，效果就很好。强化学习里的 Decision Transformer 也是这样。

把你在环境里经历的状态、动作和奖励拿出来，假装它们是一种语言，然后开始对这些序列建模。之后就可以用模型做规划，效果也不错。甚至像 AlphaFold 这样的系统也是如此。我们经常讨论分子，以及如何把分子输入模型；从计算的角度看，AlphaFold 的核心同样有 Transformer。我还想强调一点：Transformer 非常灵活，这一点我特别喜欢。举一个特斯拉的例子。假设你有一个卷积神经网络。

它接收图像，并对图像做出预测。接下来，一个很重要的问题就是：怎样把额外的信息输入进去？这并不总是显而易见。比如，我有一些额外信息，希望它影响输出；也许来自雷达等其他传感器，也许是地图信息、车辆类型或音频。你该把这些信息加到卷积神经网络的哪个地方？做拼接吗？还是相加？在哪个阶段加？而对 Transformer 来说，这就容易多了：把你想输入的任何东西切成一些块，和原有的内容一起放进一个集合，让自注意力机制自己决定这些信息应该怎样交流。结果表明，这种方法确实行得通。

所以，基本做法就是：把所有东西切开，一起扔进去。这让神经网络摆脱了欧几里得空间的束缚。以前，计算的安排要服从三维欧几里得空间的结构；仔细想想，计算本身几乎也是按照一种三维空间的布局来发生的。而在注意力机制里，一切都只是集合。所以，这是一个非常灵活的框架，你可以把各种东西都放进去。

提问者：你刚才提到，要处理不同类型的数据。

提问者：具体是怎么做的？不同的数据会用不同的 token，还是怎样？

Karpathy：对，比如你把图像切成一块块，前面的一千个 token 或者多少个 token 就是这些图像块。接下来，还有雷达的数据。其实我不太清楚雷达原生的数据表示是什么样的，但你要做的，也是把它切开、输入进来，并且以某种方式编码，让 Transformer 知道这些数据来自雷达。

因此，你会引入某种特殊的 token，或者特殊的表示，让“这是雷达 token”这件事体现在表示中，而这个表示可以通过梯度下降来学习。车辆信息也可以通过一个特殊的嵌入 token 输入，这个嵌入同样可以学习。归根结底，它们都只是一个集合。如果需要，你可以给这些集合里的元素加上位置编码。

位置编码的意思是，你可以把坐标之类的信息预先写死，比如用正弦和余弦函数编码。但更好的方式可能是不要把位置编码写死，而是在每个位置放一个向量。不管那里出现什么内容，都加上这个向量，再通过反向传播训练这个向量。就是这样。

提问者：这些方法似乎是有效的，但有时候，是不是把某些结构或其他约束固定下来，会更好？

Karpathy：我不确定有没有完全理解你的问题。位置编码本身其实只有很少的归纳偏置。它们只是一直放在某个位置上的向量，你想通过这种方式给网络一点帮助。我觉得这个直觉是好的，但如果数据足够多，通常额外干预它反而不是好事。如果数据集本身已经包含了足够的知识，再人为把知识塞进去，往往并没有什么收益。

所以，这确实取决于你所处的规模。

如果有无限多的数据，你反而会希望编码进去的先验越来越少，事实证明这样效果更好。如果数据很少，你就确实希望加入一些偏置。比如，数据集小得多时，卷积可能是个好主意，因为卷积滤波器会带来相应的结构偏置。Transformer 本身非常通用，但你也可以调整编码方式，加入更多结构。比如，使用固定的正弦和余弦编码。或者，也可以直接修改注意力机制：假设我的图像被切成了多个图像块……

我可以规定，这一块只能和附近的区域交流。你只需要在注意力矩阵里，把不希望发生的通信屏蔽掉。人们经常尝试这样的做法，因为完全注意力的计算效率不高。比如，可以交替安排两类层：一类只在局部小区域里交流，另一类进行全局交流。诸如此类的技巧有很多。

这样就能逐步加入更多归纳偏置。不过，这些偏置是从 Transformer 的核心结构里分离出来的，主要体现在节点之间怎样连接，以及位置如何编码这两个方面。

从手工特征到统一的神经网络架构

下面补充一点背景：为什么会有这门 Transformer 课程？讲这些历史时，我觉得自己有点像那边的比尔博。不知道你们有没有看过《指环王》。我大约在 2012 年全身心进入 AI 领域，也就是大约十年前。顺便说一句，那时候你甚至不会说自己在做“AI”。

那在当时几乎是个不太体面的词。现在当然可以大大方方地说了。但那时候，你甚至不会说“深度学习”，如果想让人觉得你是认真做研究的，就得说“机器学习”。现在，“AI”这个词应该又可以用了。你们大概就在现在这个时候进入这个领域，可能还没意识到变化有多大。回到 2011 年左右，我具体做的是计算机视觉，当时的处理流程大概就是这样。如果你想给图像分类，就会去看论文。这里这篇就很有代表性。

从语言模型到注意力机制

先从 2003 年讲起。我很喜欢这篇论文，它是最早将神经网络用于语言建模、并产生广泛影响的工作之一。这里的任务，就是预测序列中的下一个词，因此可以构建文本生成模型。论文当时使用的是多层感知机。

也就是一个非常简单的神经网络。它接收三个词，预测序列中第四个词的概率分布。在当时，这已经是很好的做法。后来，人们开始把神经网络用于机器翻译，于是就有了 2014 年那篇影响很大的序列到序列论文。这里的主要问题变成了：我们不只是想拿三个词来预测第四个词，而是想把一个英语句子转换成一个法语句子。关键在于，英语句子可以有任意数量的词，法语句子也可以有任意数量的词。

怎样设计一个能处理这种可变长度输入的架构？这篇论文使用了 LSTM。它大体上分成两部分，这里有些内容被挡住了。左边是一个编码器 LSTM，逐个读入单词，不断积累已经读到的上下文。然后，它把得到的向量作为条件，传给解码器 RNN 或 LSTM。解码器再一步一步生成序列中的下一个词，把英语翻译成法语，或者做类似的事情。

但人们很快就发现了一个大问题，并试图解决它，这就是所谓的“编码器瓶颈”。整个作为条件的英语句子，都要被压缩到一个向量里，再从编码器传给解码器。一个向量可能要保存太多的信息，这看起来不太合理。于是，大家开始寻找缓解编码器瓶颈的方法。这就引出了《通过联合学习对齐与翻译进行神经机器翻译》这篇论文。

引用一下论文摘要里的意思：“我们推测，使用固定长度的向量，是提高基本编码器—解码器架构性能的一个瓶颈。因此，我们提出一种扩展方法，让模型能够自动地在源句子中软性搜索与预测目标词有关的部分，而不必显式地构造这些部分或硬性的切分。”也就是说，通过这种软搜索，模型可以回过头去查看来自编码器的词。

当你在解码、生成这些词时，可以通过论文提出的软注意力机制，回头查看编码器中的词。我印象中，这是我第一次看到注意力机制。

来自编码器的上下文向量，是编码过程中各个词的隐藏状态的加权和。这个加权和里的权重，来自一个 softmax；而 softmax 的输入，则是当前解码状态与编码器生成的各个隐藏状态之间的相容程度。看到这里，你就会开始认出今天注意力机制的公式。我第一次见到它，就是在这篇论文里。据我所知，这也是第一次用“注意力”这个词来称呼这种机制。

我还专门去追了一下注意力机制的历史。我和这里的第一作者 Dzmitry 有过邮件往来，给他写信说：“这太有意思了。”

“Transformer 已经席卷了整个领域。后来成为 Transformer 核心的软注意力机制，你当初到底是怎么想到的？”没想到，他给我回了一封很长的邮件，内容非常精彩。这里是其中一段。他说，当时一直在寻找办法，绕开编码器和解码器之间的瓶颈。他曾尝试用游标遍历序列，但效果不太好。后来有一天，他想到：“如果能让解码器 RNN 自己学会搜索，决定把游标放在源序列的什么地方，应该会很好。”

“这个想法有一部分来自我中学学英语时做的翻译练习。翻译时，视线会在原文和译文之间来回移动。”我觉得这特别有趣：英语不是他的母语，而这一点反而让他在机器翻译问题上获得了优势，先带来了注意力机制，后来又带来了 Transformer。这段故事很迷人。

“我把软搜索表述为 softmax，然后对隐藏状态做加权平均。让我非常兴奋的是，第一次尝试就成功了。”这确实是一段很有意思的历史。后来他们觉得，原先起的名字 RNNsearch 有点平淡。临近论文定稿、最后几次通读的时候，Yoshua 提出了一个更好的名字：attention，也就是注意力。所以，《Attention Is All You Need》原本说不定会叫《RNNsearch Is All You Need》。我们得感谢 Yoshua Bengio，让这个名字好听了一些。大概就是这样的历史，我觉得挺有意思。

接着就到了 2017 年的《Attention Is All You Need》。在 Dzmitry 的论文里，注意力只是一个小部件，旁边还有双向 RNN、其他 RNN 和解码器等等。而这篇“只需要注意力”的论文说：那些都可以删掉。真正让系统表现很好的，就是注意力本身。所以，删掉其他东西，保留注意力。更了不起的是，通常论文只会做很小的增量改进：加一个东西，让结果再好一点。但这篇论文感觉是同时把多个东西组合在了一起。

它们以一种非常独特的方式组合起来，在架构设计空间里找到了一个很好的局部最优点。所以，我认为这是一篇真正的里程碑式论文，非常了不起，背后应该做了大量工作。删掉所有 RNN，只保留注意力。但因为注意力操作的对象是集合，这一点我马上会展开，所以现在你需要给输入加上位置编码。注意力本身没有空间概念。哎，我得小心一点。

他们采用了来自 ResNet 的残差网络结构，把注意力与多层感知机交替安排起来，使用了另一篇论文提出的层归一化，还引入了多个注意力头并行工作的概念。此外，他们给出了一套相当不错的超参数，直到今天仍在使用。比如，多层感知机中间层的维度扩展倍数是 4 倍。

我们稍后会讲得更具体。这个 4 倍一直沿用至今。我相信有很多论文尝试调整 Transformer 的各种小细节，但大多数改动都没有真正留下来，因为原来的设计已经很好了。据我所知，一个真正保留下来的改动，是调整层归一化的位置，改成预归一化版本。你们在这里看到，层归一化原本放在多头注意力和前馈网络之后，后来人们把它放到了前面。

除了移动层归一化的位置，今天看到的 GPT 等模型，基本还是五年前、2017 年提出的那套架构。即使所有人都在研究它，它仍然表现得非常稳固，这一点很有意思。当然，位置编码方面也有一些得到采用的创新，比如现在更常使用旋转位置编码、相对位置编码等等。

所以，变化确实是有的，但整体上，它经受住了很多检验。

好。真正有意思的是，随着上下文里提供的例子增加，准确率也会提高。这暗示，Transformer 能以某种方式在激活值中学习，而不必像常规微调那样执行梯度下降。微调时，你要提供例子和答案，再通过梯度下降进行训练。但 Transformer 读题的时候，内部权重所实现的计算，似乎就在做某种可能类似梯度下降的事情，也就是某种元学习。论文区分了两个循环：用随机梯度下降进行训练的外循环，以及上下文学习的内循环。

内循环发生在 Transformer 读取序列的过程中，外循环则是梯度下降训练。也就是说，当 Transformer 读入一个序列时，它的激活值里可能发生了某种学习过程，而且这个过程也许非常像梯度下降。最近已经有一些论文在研究、探讨这种可能性。比如这里这篇论文提出了一种叫 RAW 的算子，论证 Transformer 可以实现这个算子，然后展示如何用 RAW 算子实现岭回归之类的算法。

所以，有些论文在提示我们：Transformer 的激活值内部，也许存在类似基于梯度的学习过程。我觉得，这并不是无法想象。基于梯度的学习是什么？前向传播、反向传播、更新。这个过程看起来很像残差网络，对吧？因为你只是在原来的权重上加一个改变量。

从一组初始随机权重开始，做前向传播、反向传播、更新权重，再做前向传播、反向传播、更新权重。它看上去就像 ResNet，而 Transformer 本身也是一种残差网络。当然，这个解释比较粗略，但确实有人在尝试说明，为什么这种事情有可能发生。最后，我还复制粘贴了几条自己的推文。它们本来是写给普通读者看的，所以比较概括，也稍微带一点兴奋的语气。

我讨论的是：这个架构为什么这么有意思，为什么可能会变得如此流行。我觉得，它同时兼顾了三个非常理想的性质。第一，Transformer 的前向计算有很强的表达能力，能够实现非常有意思的函数，甚至可能实现元学习。第二，得益于残差连接、层归一化等设计，它很容易优化。第三，它的效率极高。这一点不总是受到足够重视，但如果你看它的计算图，就会发现它是一个浅而宽的网络，非常适合发挥 GPU 的并行能力。

因此，我认为 Transformer 的设计，是非常有意识地在追求 GPU 上的高效运行。我也很喜欢之前的一些工作，比如 Neural GPU。它们关心的就是：怎样设计在 GPU 上高效运行的神经网络？从硬件的约束出发，反过来推导网络应该怎样设计。我觉得这是一种非常有意思的思考方式。总之，这篇论文确实很值得研究。

把注意力看成有向图上的通信

现在，我想深入讲讲注意力机制。我对它的理解方式，和以前见过的一些讲法不太一样，所以想尝试从另一个角度来讲。在我看来，注意力就是 Transformer 的通信阶段，而 Transformer 会交替进行不同阶段。

一个是通信阶段，也就是多头注意力；另一个是计算阶段，也就是多层感知机，或者说 MLP。通信阶段本质上就是：在有向图上，根据数据内容来传递消息。先把机器翻译之类的背景都忘掉，我们现在只有一个有向图，每个节点上都存着一个向量。下面要讲的，就是这些向量在通信阶段怎样沿着有向图彼此交流。后面的计算阶段则很简单：用多层感知机分别处理每一个节点。

这些节点到底怎样在有向图上交流呢？我写了一点简单的 Python 代码，实现一轮以注意力为消息传递机制的通信。这里，每个节点都有一个自己的数据向量，你可以把它看成这个节点的私有信息。它还可以发出一个键、一个查询和一个值，也就是 key、query、value。产生它们的方法很简单，就是对节点的向量做线性变换。

查询表示：“我在寻找什么？”键表示：“我有什么？”值则表示：“我要传递什么？”于是，假设你有一张图，由一些节点和任意的有向边构成。要让这些节点交流，就以某种任意顺序遍历所有节点。来到一个节点时，先得到它的查询向量 Q。它的意思是：“我是图中的一个节点，这就是我正在寻找的信息。”这个查询向量，就是通过这里的线性变换得到的。

接下来，看看所有指向这个节点的输入节点。它们会广播“我有什么”，也就是各自的键。它们广播键，而我手里有查询。

然后，让查询与这些键做点积，就能得到分数。简单地说，点积给出了一个还没有归一化的权重，表示那些指向我的节点所拥有的信息，与我正在寻找的内容有多相关。再用 softmax 归一化，让这些权重加起来等于 1。这样，我们就得到了一个概率分布，然后用这些权重对各个节点的值做加权求和，得到自己的更新量。

所以，整个过程就是：我有查询，它们有键；做点积，得到相关程度，也可以叫亲和度；用 softmax 归一化；最后，让那些值按权重汇总、流向我，更新我的状态。每个节点都独立地经历这个过程，最后再统一更新。这种消息传递方式，就是 Transformer 的核心。

实际实现会采用更充分的向量化和批处理，因此看起来更难理解；中间还会穿插层归一化等操作，让训练表现更好。但从高层次看，注意力机制里发生的事情，大致就是这样。

在 Transformer 的通信阶段，这种消息传递会在每个注意力头里并行发生，再沿着各层依次进行，每一次使用不同的权重。多头注意力基本就是这么回事。因此，看编码器—解码器模型时，你可以从图中节点的连接方式来理解：编码器里的所有 token，也就是我们希望模型依据的那些条件信息，彼此之间是全连接的。

所以，在计算它们的特征时，它们之间可以充分交流。但解码器是在做语言建模，我们不希望未来的 token 向当前 token 传递信息，因为那样会泄露当前这一步的答案。因此，解码器里的 token，可以接收所有编码器状态的信息，也可以接收解码序列中所有先于自己的 token 的信息。这样，有向图里就会形成一种三角形结构。这就是它实际实现的消息传递方式。

这里还要注意：在解码器的交叉注意力中，使用的是编码器最顶层的特征。你可以这样想：编码器里的所有节点、所有 token，已经反复互相查看、交流了很多次，充分弄清了里面有什么；而解码器去看的，是它们最顶层的表示。

消息传递的方式大概就是这样。我本来还打算继续讲 Transformer 的具体实现。

提问者：能不能再讲一下自注意力和多头注意力？它们到底是什么？

Karpathy：好。多头注意力，就是把刚才那套注意力机制并行应用多次。多个头，意味着同一种注意力的多个独立实例。也就是让这套消息传递同时发生多次，每一次都使用不同的查询、键和值的权重。

你可以把它想成：我同时从不同节点寻找不同种类的信息，然后把它们全都收集到同一个节点里。所有这些过程是并行的。所以，“头”基本就是把同一个过程复制多份、并行运行；而“层”则是复制多份、串行运行。这样说也许比较好理解。

至于自注意力，它说的是每个节点都从自身产生键、查询和值。按照我刚才描述的方式，这其实就是自注意力，因为每一个节点的键、查询和值，都来自这个节点本身。交叉注意力则不同。这里有一处来自编码器的交叉注意力：查询仍然由当前节点产生，但键和值，则根据编码器那边的节点来生成。

比如，我正尝试解码序列中的第五个词，因此我有自己的查询，想寻找与这个位置有关的信息。而能回答这些查询的信息源，也就是键和值，可以来自当前解码序列前面的节点，也可以来自编码器的最顶层。编码器里的那些节点已经反复看过所有输入 token，现在可以广播它们所包含的信息。

所以，总结一下：交叉注意力和自注意力的区别，只在于键和值来自哪里。它们可以由当前这一组节点生成，也可以来自某个外部来源，比如编码器及其节点。但从算法上说，使用的数学运算是一样的。

从 nanoGPT 代码理解 Transformer

这些节点本质上就是向量。我直接讲实现好了，之后也许就能把它和图的概念联系起来。至少先带着刚才的直觉，来看 nanoGPT。这是一个非常精简、但完整的 Transformer 实现。我过去几天一直在做这个项目。这里是在 OpenWebText 上复现 GPT-2 的结果，所以它其实是个相当认真的实现。只要算力足够，它确实可以复现 GPT-2。如果我没记错，这里用了一台 GPU 计算节点，训练了大约 38 个小时。代码只有 300 行，可读性很高。

大家都可以去看看。我来快速带你们过一遍。我们先做一个仅含解码器的 Transformer，也就是一个语言模型。它要建模的，是序列中的下一个词，或者下一个字符。所以，用来训练的数据总是某种文本。这里有一些“莎士比亚”……准确说，这里是真正的莎士比亚作品，我们接下来要生成仿写的莎士比亚文本。这叫 tiny Shakespeare 数据集，是我最喜欢的几个玩具数据集之一。

把这些莎士比亚文本拼接起来，就得到一个大约 1 MB 的文件。然后可以用它训练语言模型，生成无穷无尽的“莎士比亚”，我觉得挺好玩的。现在我们有了文本，第一件事，是把它转换成一个整数序列。你不能把原始文本直接塞进 Transformer，需要先编码。最简单的做法，是给每个字符分配一个整数。于是，原来的“hi there”就会变成这样一串整数。

每个字符都编码成整数后，就得到一个很长的整数序列。把所有内容拼成一个长长的一维序列，就可以在它上面训练了。这里我们只有一个文档。如果有多个相互独立的文档，人们通常会引入特殊 token，用文本结束标记把不同文档隔开，形成边界。不过，这些边界实际上并没有什么……好，接下来我们要构造批次。

所谓一批数据，就是回到这个一维序列里，从中截取一些片段。

假设 block size 是 8。block size 表示 Transformer 最多能处理多长的上下文。如果它等于 8，就意味着模型最多用前面 8 个字符，来预测第 9 个字符。batch size 则表示，我们同时并行处理多少条序列。我们希望这个数尽可能大，好充分利用 GPU 及其并行计算能力。在这个例子里，批次的形状是 4×8。

所以，这里的每一行都可以看成一个独立样本，每行都是从原始序列里截取出来的一小段，我们会用它们来训练。

而且，每一个位置都有输入和对应的目标。为了讲清楚，一个 4×8 的批次对 Transformer 而言到底包含了什么，我在这里把它展开了：当输入只有 47 时，目标是 58；当输入是序列 [47, 58] 时，目标是 1；当输入是 [47, 58, 1] 时，目标是 51；依此类推。因此，一个 4×8 的批次，实际上包含了许多个独立的预测样本，我们希望 Transformer 同时从这些样本中学习。

你可以看到，批次中的不同序列彼此独立地训练，而这里横向的时间维度，也是并行训练的。所以，从预测样本的数量看，实际更接近 B×T。只不过，沿着 T 这个方向进行预测时，可用上下文的长度会逐渐增加。这就是模型从这个批次中学习到的全部样本。

现在来看 GPT 这个类。因为这是一个仅含解码器的模型，所以没有编码器。我们不是要把某个英语句子翻译成别的语言，也不是要依据另一份外部信息生成内容；我们只是想生成一串很可能接续出现的词。这里全部都是 PyTorch 代码。我讲得稍快一些，因为我假定大家已经上过 CS231 之类的课程。

在前向传播里，我们接收这些整数索引，然后通过嵌入查找表来编码它们的身份。对每个整数，我们都在 nn.Embedding 这个向量查找表里索引，取出对应 token 的词向量。不过，Transformer 原生处理的是集合。

所以，还需要给这些向量加上位置编码。这样我们既知道 token 是什么，也知道它位于序列中的哪个位置，从 1 到 block size。这里把“是什么”和“在哪里”这两类信息直接相加，也就是把 token 嵌入与位置嵌入相加，正如代码里所示。然后还可以选择加入 dropout。

于是，这里的 X 就包含了这些词以及它们的位置。接下来，把 X 送进 Transformer 的各个块。我们马上会展开看块里有什么；现在先把它们理解成依次排列的一系列 Transformer 块。最后，再做一次层归一化，然后通过线性投影，把 Transformer 的输出映射成序列中下一个词、也就是下一个整数的 logits。

这里的 lm_head 是 language model head，也就是语言模型头的缩写，它只是一个线性函数。整个过程就是：给所有词加入位置编码，送进一系列块，再通过线性层得到下一个字符的预测分布。如果我们还提供了目标，也就是数据加载器产生的那些目标，你会发现它们其实就是把输入在时间上向后错开一位，那么就可以用这些目标计算交叉熵损失。它是负对数似然，也就是常见的分类损失。现在，我们深入看看这些块。

这些块是依次应用的。正如前面所说，每个块都有通信阶段和计算阶段。通信阶段里，各个节点会彼此交流。如果 block size 是 8，那么图中就有 8 个节点。第一个节点只有自己指向自己。

第二个节点由第一个节点和它自己指向；第三个节点由前两个节点和它自己指向；依此类推。这里一共有八个节点。

X 沿着残差路径向前传递。我们从这条路径取出 X，先做层归一化，再做自注意力，让这八个节点交流。不过，别忘了 batch size 是 4，所以这个过程还会同时应用到四个样本上。也就是说，有四组各含八个节点的图，每组内部独立通信，批次维度之间不会交叉通信。好在这里也没有批归一化。交换完信息之后，再用多层感知机来处理各个节点，这就是计算阶段。

这里没有交叉注意力，因为这是一个仅含解码器的模型。我们只有多头注意力这一步，对应代码里的这一行，也就是通信阶段；还有前馈网络，也就是 MLP，对应计算阶段。我稍后再回答问题。

MLP 很简单，就是对每个节点单独处理，变换这个节点的特征表示。它是一个两层神经网络，中间使用 GELU 非线性激活；你可以先把 GELU 理解成类似 ReLU 的东西，总之就是一个非线性函数。MLP 没有什么特别复杂的。接下来是因果自注意力部分，也就是通信阶段。

这是整个实现的核心，也是最复杂的部分。

它复杂，主要是因为批处理，以及怎样在实现里屏蔽图中的某些连接。预测一个 token 时，不能从未来获取任何信息，否则就等于提前泄露了答案。比如，我现在要预测第五个 token，输入的是第四个 token，并且会注意第三、第二和第一个 token，试图判断接下来应该是什么。但在同一个批次里，沿时间维度往右挪一个位置，答案就已经作为输入摆在那里了。

所以，我不能从那个位置获得任何信息。这就是实现起来比较绕的原因。不过，前向传播的基本做法，是先根据 X 计算查询、键和值。

这里就是键、查询和值。计算注意力时，用查询矩阵与键矩阵相乘。这相当于把所有注意力头里的所有查询与所有键之间的点积，并行计算出来。我刚才漏说了一点：注意力头这个维度也在这里并行处理。所以，我们既有批次维度，又有时间维度，还有注意力头维度，最后弄出了五维张量，看起来非常混乱。建议你们之后自己一步步过一遍，确认它确实在做正确的事。

基本上，就是批次维度、注意力头维度、时间维度，以及相应的特征。这段实现会针对每个批次元素、每个头、每个时间位置，执行我之前那段简单 Python 代码里的计算，也就是查询和键的点积。然后执行 masked_fill：把那些不应该通信的节点之间的注意力分数设为负无穷。

之所以用负无穷，是因为接下来要做 softmax。负无穷经过 softmax 后，对应位置的注意力权重就会变成 0。这样，我们就得到了各个节点之间的权重，也就是它们的亲和程度。

之后可以选择加上 dropout。接着，注意力矩阵与 V 相乘，就是按照刚才算出的亲和度收集信息，也就是对那些节点上的值做加权求和。所以，这个矩阵乘法做的就是加权求和。再后面是 transpose、contiguous、view 这些操作，因为实现使用了复杂的批处理和高维张量；这些操作并没有引入什么新的核心计算。然后可以再加 dropout，最后通过线性投影回到残差路径。

这就实现了基本的通信过程。接下来，你可以训练这个 Transformer，再让它生成无穷无尽的“莎士比亚”。生成方式很简单：这里 block size 是 8，我们先从某个起始 token 开始，比如用换行符作为起始 token。因为此时只有一个节点，它只能和自己交流。模型给出序列中第一个字符的概率分布，然后从中解码出第一个字符。

得到这个字符之后，再把它送回来，编码成整数。现在，序列里就多了一个元素。我们知道它处于哪个位置，也知道它对应哪个整数，再加上位置编码，一起送进 Transformer。这个新 token 现在就能与第一个 token 交流，了解它的身份。如此不断把输出送回输入。等长度达到 block size，也就是 8，就必须开始截断，因为按照这个模型的训练方式，输入长度不能超过 8。

所以，上下文会越来越长，一直增长到 8。如果还想继续生成，就要开始裁剪，因为这个 Transformer 在时间维度上只能处理 8 个元素。以最朴素的实现来说，这些 Transformer 都有有限的 block size，也就是上下文长度。典型模型可能是 1,024 个或 2,048 个 token 左右。不过，这些 token 通常是 BPE、SentencePiece 或 WordPiece 之类的编码单位，编码方式有很多种，所以能容纳的内容也没有特别长。这也就是我前面提到的问题。接下来再看编码器的注意力。

编码器、自注意力与交叉注意力

你只需要把屏蔽注意力的这一行删掉。如果不加掩码，所有节点都可以互相交流，所有连接都被允许，信息就能在所有节点之间流动。所以，如果想实现编码器，编码器里的所有块只要使用删掉这一行的注意力机制就行了，就这么简单。

假设编码器里有 10 个 token，也就是 10 个节点。沿着 Transformer 的各层向上处理时，它们全都可以彼此交流。如果还想实现交叉注意力，得到一个完整的编码器—解码器 Transformer，而不只是像 GPT 那样仅含解码器的模型，就需要在中间再加入交叉注意力。这样，一个块里会有自注意力、交叉注意力和 MLP 三个部分。交叉注意力要从编码器最顶层获取特征。

这里需要再加一行，放入交叉注意力。我应该直接把它实现出来，而不是只在这里指来指去。不过，总之，这里会多一行交叉注意力，于是变成三行，因为我们加入了另一个子模块。查询来自 X，而键和值来自编码器的最顶层。信息从编码器单向流入 X 中的所有节点，就是这样。

所以，这些都只是在解码器注意力的基础上做一些很简单的修改。

你经常会听到这些说法：像 GPT 这样的仅解码器模型，像 BERT 这样的仅编码器模型，以及像 T5 这样、可以用于机器翻译等任务的编码器—解码器模型。不过，BERT 不能用这里这种自回归语言建模的方式来训练，也就是不断预测序列中的下一个 token。它使用的训练目标有所不同。你把整个句子放进去，让句子里的内容充分互相交流，然后可以做情感分类之类的事情；它并不是在建模序列中的下一个 token。

所以，它们的训练方式会有些不同，会用掩码以及其他去噪技术。这方面大概就是这样。

为什么表达能力之外，还需要可优化性与效率

对于 RNN，我会说：原则上，是的，它们可以实现任意程序。但在某种程度上，我觉得这个说法没有太大用处。就表达能力而言，它们也许足够强，可以实现任意函数；但它们不好优化，而且肯定不够高效，因为它们是一种串行计算装置。

如果从计算图来看，RNN 的图非常细长。把神经元及其连接全部展开、画出来，你就会看到一张很长的图。这不理想，对优化也不利。具体原因我不能完全说清楚，但直觉上，反向传播时，你不希望经过太多步。而 Transformer 是一张浅而宽的图，从监督信号到输入，只需要很少的几跳。

而且，这些路径沿着残差连接，梯度很容易流过。还有层归一化，用来控制各处激活值和梯度的尺度。路径没有那么多跳，从监督信号很快就能到达输入，梯度可以顺畅地流过整张图。而这些计算又都可以并行完成。

因此，你不必像编码器—解码器 RNN 那样，先处理第一个词，再处理第二个词，再处理第三个词。在 Transformer 里，各个词基本上可以完全并行处理。这些性质都很重要。其中第三点，也就是效率，讨论得比较少，却极其重要，因为在深度学习里，规模很重要。你能训练多大的网络，影响非常大。如果一种架构能在现有硬件上高效运行，你就能把它做得更大。

所以，这里我说，如果让我来命名，我也许会把 Transformer 称为“通用、高效、可优化的计算机”，而不只是“你只需要注意力”。

至少事后回看，我可能会给那篇论文起这样一个名字。它提出的模型非常通用：前向计算有很强的表达能力，GPU 使用效率很高，又容易通过梯度下降来优化，训练起来很顺畅。这里还有几条我比较热门的推文。

大家可以之后再看。我觉得这一条可能很有意思：如果过去的神经网络，是为特定任务设计的专用计算机，那么 GPT 就是一台通用计算机，可以在运行时重新配置，执行自然语言程序。程序通过提示词给出，GPT 则通过续写文档来执行程序。

我个人真的很喜欢把它类比成计算机。它就是一台强大的计算机，而且可以通过梯度下降来优化。好，这些内容你们稍后可以再看，我先把这一页留在这里。抱歉，我刚刚才找到这页幻灯片。

事实证明，如果扩大训练集，并使用足够强大的神经网络，比如 Transformer，网络就会变成某种处理文本的通用计算机。我觉得，这是理解它的一个很好的角度。它不再只是执行某个固定的操作序列，你可以在提示词里设计这个序列。由于 Transformer 本身足够强大，又在规模足够大、难度足够高的数据集上训练过，它便在某种意义上成为了这样一台通用的文本计算机。我觉得，这种看法很有意思。
