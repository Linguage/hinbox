访谈概述

本次访谈发生在未来的时间点（文本背景设定在2026年5月左右），播客主持人 Lenny Rachitsky 邀请了 Every 的创始人兼 CEO Dan Shipper 作为嘉宾。一年前，Dan 曾准确预测了 Claude Code 在非技术工作中的爆发。在本次播客中，Dan 基于他团队“全员极客”的实验性工作模式，对未来一年内 AI 将如何改变我们的工作方式、工作形态以及哪些职业将成为最大赢家做出了极为大胆且反共识的预测。

核心观点包括：

  1. 工作界面的重构： 几乎所有的知识工作都将迁移到类似 Codex 或 Claude Co-work 的本地 AI 桌面环境中完成，传统的 SaaS 软件将内嵌在这些 AI 智能体的环境里被调用。
  2. 看好 SaaS 行业： AI 不会消灭 SaaS，反而会因为“智能体”作为海量新用户的加入，让 SaaS 的使用量和价值飙升。
  3. 命令行（CLI）时代的终结： 尽管近期 CLI 交互很火，但更直观的 GUI 交互依然会是未来的主导。
  4. AI 时代的职场赢家： 产品经理（PM）和全栈设计师将是最大的受益者。他们可以直接通过 AI 辅助编程完成产品交付，而不需要依赖庞大的工程团队。
  5. AI 不会带来失业潮： 自动化是一个伪命题，AI 模型只是让“过去的专业技能”变得廉价（产生大量同质化的“Slop”），人类的价值在于如何利用这些新工具去创造新的专业知识。我们需要做的是“驾驭模型（Ride the models）”。

未来一年工作方式的改变

Dan Shipper： 这是我最喜欢的问题之一。因为如果你去看目前的基准测试（Benchmarks），你只会得出一个结论：“AI 马上就要抢走我们所有的工作了。”

SWE-bench 等评测有一个很酷的标准，它衡量最新模型自主完成任务的时间。比如最近大家都在恐慌的那个大型 Anthropic 模型 Mythos Preview，它能够以 50% 的准确率自主完成长达 17 小时的任务。这确实非常疯狂，而且模型的发展呈指数级上升，这也是真实的。

但我的经验和直觉是，一年后当我们回首时会发现：人类其实有更多的工作要做。 即便模型完成工作的能力越来越强，人类反而有更多的事情要处理，这其中存在一个非常有趣的悖论。

我对未来一年工作方式改变的最大预测是，它将主要在智能体（Agents）的使用上产生两种分化。

第一，大家会回到我们五年前想象的那种模式： 公司里的每个人都会有至少一个能跟他们对话、能被委派工作的智能体。我们稍后会讨论它的具体形态，但它本质上就像 Open Claw 一样。

第二，你所做的大部分工作，实际上将发生在你的电脑上，在一个类似于 Codex 或 Claude Co-work 的环境中。 这个环境会成为你完成所有工作（无论是收发邮件、创建文档等）的“操作系统”。这将成为一块非常明确的竞争高地。

我想按顺序讲讲这两点。

Lenny Rachitsky： 所以第一点是，你会有可以在 Slack 或其他任何地方向其委派任务的智能体？

Dan Shipper： 没错。关于第一点，很有意思的是它未来的架构并不明确。是每个人都拥有一个私人智能体？还是每个团队拥有一个？是全公司只有一个统管的智能体？还是说智能体会变得专业化，形成一个平行的“影子组织架构”？

当 Open Claw 刚问世时，我们 Every 内部所有人都用上了它，我当时非常坚信未来就是“每个人都有自己的私人智能体”。这种平行组织架构的概念非常吸引人。在那种世界里，智能体就像是你个人的小投影，这真的很酷。你读过《黑暗物质（The Golden Compass）》吗？就像你的肩膀上停着一只你的守护神（Daemon），它是你灵魂的一部分。我真的觉得事情本来是朝那个方向发展的，所以我以前非常痴迷于私人智能体。

但我现在完全倒戈了。

我现在真的认为，当前的模式将会是“超级智能体（Super Agent）”——即整个公司共用一个智能体。你已经开始在一些公司看到这种现象了。比如 Shopify 出了名地有一个，Ramp 现在也有一个。我觉得这里面有一些非常有趣的原因。虽然我认为私人智能体最终还是会到来。

但我们发现，当 Open Claw 的热潮消退后，大家一开始都说：“我要装一个，太酷了。”然后大家发现这玩意儿太费劲了。它经常崩溃，我得不停地去鼓捣它，我得通过 SSH 连进服务器去修复乱七八糟的设置。大多数人为了完成工作，就是不想花这个时间，或者没能力花这个时间。

驱动这一现象的根本原因在于：无论是 Open Claw 还是任何其他框架，目前的 AI 智能体要想真正好用，它非常需要一个关心它的人类。 它需要与某个特定的、能随时盯着它并确保它在做正确事情、对大家有用的“人”建立联系。一旦你切断了这种联系——比如一旦有人说：“啊，我不想再去维护这个蠢毙了的 Open Claw 了”——那么这个智能体立刻就变得没那么有用了。

这就是为什么我认为趋势开始转向“每个公司一个智能体”的模式。因为目前理想的状况是：你设立一个“前沿部署工程师（Forward Deployed Engineer）”或具有类似技能的人，专门负责确保这个智能体对全公司都能正常运作。然后也许你再往下设立一些小型的团队智能体。

我认为随着模型变得更加独立，这种模式会向下延伸，我们会更可能拥有不需要我们去捣鼓内部设置的私人智能体。但在我们和许多其他公司（包括模型公司自己）中行之有效的模式是，从异步智能体的角度来看，这更像是一个自上而下的过程：顶层有一个智能体，它可能什么都能做，但通常它负责你们决定的全公司都需要的那类特定工作，比如数据查询请求。

它会从顶层开始，然后逐渐渗透到各个部门，随着大家越来越习惯这些使用场景，智能体会变得更加专业化，而且不那么需要人们频繁地去“修修补补”了。其核心机制就是：智能体需要关心它们的人。

Dan Shipper： 完全正确。

Lenny Rachitsky： 预测它们主要会在 Slack 里面运作吗？为了工作？

Dan Shipper： 是的，这很合理。虽然人们很喜欢 Open Claw 上的“蓝气球”提示，如果能在 iPhone 上使用的话。但我认为人们心理上有一种微妙的需求，他们真的希望把个人生活和工作用的智能体分开。

我们的首席运营官 Brandon Gall 把处理个人事务称为“电脑跑腿（Computer Errands）”。比如“帮我订点杂货”之类的，我觉得个人智能体在这个领域会有巨大的应用空间。但我们目前主要关注的是工作场景。所以我认为在工作端，主要还是会在 Slack 发生。

Codex 和 Claude Code 将成为新的工作操作系统

Lenny Rachitsky： 太棒了。我们来谈谈你提到的第二个工作界面吧？

Dan Shipper： 当然！我太期待聊这个了，我觉得这是最酷的一件事。

基本上，发生的事情是：Anthropic 在某个节点意识到，如果你在你的电脑上安装了一个智能体（Claude Code），并且它直接在你的电脑上运行，那么它就拥有了你拥有的一切访问权限。它使用终端，所以它本质上拥有超级访问权限。不仅如此，这些智能体真的非常懂如何使用终端，因为网上关于这方面的内容太多了。

这创造了一种极其强大的编程范式。Anthropic 真的是第一批做到这一点的。在很长一段时间里，我认为 OpenAI 在这方面非常落后，但最近在我看来，他们已经反超了。这非常有趣。

当人们仍然认为编程智能体或者编程模型主要只是“结对程序员（Pair Programmers）”的时候，Anthropic 是最早站出来说“不，不仅如此”并且成功实现的公司之一。在他们之前也有人尝试，比如 Devin 拥有大型云环境，OpenAI 也尝试过，但真正的普及似乎是在把它直接放在你的本地电脑上之后才发生的。

他们弄明白了这一点。然后我想，他们和他们的社区一起发现，一旦你的电脑上有了一个能构建任何东西的编程智能体，它实际上也能胜任你想要做的任何类型的工作。

人们开始通过“黑客手段”改造 Claude Code，让它去完成他们所有的日常工作。接着 Anthropic 开发了 Co-work——算是给 Claude Code 套上了一个更漂亮的外壳，但底层逻辑是一样的。

我认为 OpenAI 下了几步不同的棋。他们早期版本的 Codex 非常技术向，非常聪明，但有点“自闭症”的感觉。它听不懂你的言外之意，只能绝对字面地理解你的指令。

大概三四个月前，大概在他们发布 5.3 模型的时候，他们开始转变方向：“哦不，我们懂了。这个模型速度很快，它非常适合用来处理通用的知识型工作任务。”然后他们推出了 Codex 的桌面版应用。如果你看看 Anthropic 从 Claude Code 演进到 Co-work 所学到的所有经验，你其实能在 Anthropic 桌面版 UI 的标签页里看到这些痕迹。我认为 OpenAI 只是觉得：“我们看到这东西要往哪走了，咱们直接跳到那一步吧。”

所以，我认为 Codex 现在在这个赛道上处于领跑地位。这两家公司会有不同的定位，这是场赛马，但我现在把 Codex 当作我的日常主力工具。我基本上所有时间都泡在里面。我偶尔会切换回 Claude，但我认为 OpenAI 找对了范式。

并且我很清楚，无论目前谁领先（以后可能还会变），所有的工作都将在这些界面中完成。比如，当我写文档时，Codex 应用内自带了一个浏览器。我只需要进入我的 Codex 线程（我每个项目都有一个对应的线程），打开内置浏览器，进入文档页面。我通常用 Proof 写作，那是我自己做的一个在线 Markdown 编辑器。然后我就让 Codex 运行着，看着我在 Proof 里操作。

Codex 能看到我在做什么，我也能看到 Codex 在做什么。所有东西都在一个地方，这正是让 Claude Code 早期如此好用的那个核心优势的延伸。我基本上觉得我有了一个平行的工作伙伴，它不仅能在文档里回应和写作，还能去查资料。它可以使用我的电脑，基本上能做我在电脑上能做的任何事。

这具有极其强大的威力。

我用它做所有事情。比如，我已经连续 10 天保持“收件箱清零（Inbox Zero）”了，了解我的人都知道这有多疯狂，我以前从来做不到。这是因为我只需要让 Codex 配合 Cora（我们的邮件智能体）收集我所有的邮件。然后它会渲染出一个小页面（我在 Anthropic 的活动上给你看过这个），我只需要对着页面开始“独白”，对着每一封邮件说话。

比如：“去查一下这个。”“哦，这是一个律师的提问。你能去收集一下过去四年里的所有相关文件，然后整理成一份报告发过去吗？”它就直接去做了。所以所有那些我以前会拖延的事情，我现在都不拖延了。

很长一段时间以来，我们一直认为，体验 AI 的最佳方式是把 AI 放进浏览器里。但我认为现在正在发生的是截然相反的情况，而且它以一种我始料未及的方式变得非常有价值：把你一直在电脑上使用的 AI 智能体，直接内置一个浏览器，这样它就能看到你正在做的所有事情。

这是一个神奇的组合，目前还非常罕见（你现在甚至在 Claude Code 里也做不到，因为他们不允许你在 Claude Code 内部浏览外部网站）。但我认为一年后这会变得极其普遍。

Lenny Rachitsky： 这听起来比表面上更具颠覆性。我听明白的是：你的预测不是将 AI 植入到各种 SaaS 工具中，而是SaaS 工具将会在 Codex 或 Claude Code 内部运行。

Dan Shipper： 这就是这件事产生的一个极其重要的二级效应。假设我在智能体里使用 Proof，或者 PostHog 等任何网站。智能体可以访问这个网站，所以它拥有我拥有的所有权限。它还能访问我的整个电脑。当我在那个网站上运行智能体时，我消耗的是我自己的 Token，而不是软件供应商的 Token，也不是这个应用本身的 Token。

这让 SaaS 回归了它应有的位置：是的，你想让它对智能体友好。现在大家都开始做 CLI 了。你想让 HTML 变得非常易用，你想确保 CLI 里发生的任何操作都能立刻在用户界面上显示出来。这里有很多需要处理的问题。但是一旦你做到了这些，你其实就不需要再去思考如何构建一个主要由用户使用的 AI 界面了。也就是说，你不需要在你的产品里原生内置一个智能体。

这是一个巨大的改变。比如，任何人使用 Proof，我都不需要为他们的 Token 买单，因为用户会把自己的 AI 带到 Proof 里。这改变了你作为一家 SaaS 公司要构建的东西：你现在需要同时为人类和智能体设计产品。这也改变了你的利润率，因为你再也不用担心为用户的 Token 买单了。

Lenny Rachitsky： 这绝对是个大事件。你描述的是，越来越多我们从事的专业工作，将仅仅发生在 Codex 或 Claude Code 中。那么 Cursor 在这其中处于什么位置？那里有潜力吗？

Dan Shipper： 这是个好问题。我认为 Cursor 也看到了同样的趋势。在某些方面，他们做了同样的事情，甚至做得更好。比如我认为 Cursor 的云端实现方式比 OpenAI 或 Anthropic 的都更先进。但 Cursor 至少到目前为止，非常明确地选择了一条赛道：他们非常明确地选择只服务于程序员。

这可能会限制他们在这个通用领域的上限。尽管“程序员”的定义正在扩大，足以给他们提供一个巨大的市场，但我不知道他们是否会跃升到“用这个来做个幻灯片”的层面。

但有一点非常清楚：每家模型公司都开始意识到，要发挥模型的最大效用，拥有一个良好的“外壳/框架（Harness）”有多么重要。所有的平台都在向这样一个世界演进：你在 OpenAI 或 Anthropic 平台上调用模型时，不再仅仅是简单的“提示词-回复”。它们实际上是在云端的一台电脑上运行这个模型，然后把结果交给你。他们知道必须提供这种环境才能获得最好的结果。

所以你看到了 Anthropic 有云托管的智能体。OpenAI 目前还没有公开的回应，但我预计那很快会发生。而现在 Cursor 基本上被 SpaceX 收购了（虽然不是完全收购，但也差不多了）。所以我认为人们开始意识到：“我不能只做模型那一层，我必须在它之上搭建一个框架。”而我认为这个框架的终极形态就是：“我能用来做任何类型的知识型工作。”

Cursor 面临的一个艰难决定将是：是否要突破仅限程序员的定位。

这将如何改变 SaaS 公司应该构建的产品

Lenny Rachitsky： 那么对于构建非 OpenAI 或 Anthropic 产品的公司来说，如果这个预测成真，随着时间的推移，人们将会在这两家的智能体内部使用你们的产品。如果你是这些公司的一员，你会为了迎接这个未来做些什么准备？

Dan Shipper： 我会全面为之做准备。举个例子，传统的生产力软件（无论是 Slack、Word 文档还是 PPT），主要都是设计给人使用的。现在大家都在做 CLI，所以这是设计给智能体脱离人类独立使用的。

我认为我们正在进入一个全新的范式：人类和智能体将同时在同一份工作上协作。 我们都在做事情，我需要清楚智能体在干什么，智能体也需要清楚我在干什么。我们必须以一种无缝的方式来回互动。

为这种场景制作的软件将会完全不同。比如，我的 Proof 省去了很多功能。我不需要做像 Word 那样的格式化工具栏、分页符或者插入表格的功能，因为智能体会直接帮我做好。我不需要操心这些，它能处理所有排版。所以你可以把产品做得比传统软件简单、轻量得多。

另外，你需要开始提供各种全新的功能交互，因为智能体与软件交互的方式截然不同。比如，智能体可以同时做很多事，它们能在一瞬间对你的文档、PPT 或代码库进行成百上千次修改。你向用户展示这些修改的方式，与展示另一个人类同时协作的方式是完全不同的。你需要“审批”机制，你需要一个类似收件箱的东西来总结“这是即将发生或已经发生的所有修改”。你需要详细的日志，以及一键快速回滚的能力。

因为智能体与软件互动的方式极其特别，底层的基础设施要求也不同。智能体可以在 3 秒内发起 10 亿次请求，你打算怎么应对？这正是 GitHub 现在遇到麻烦的原因，使用 GitHub 的用户数量呈指数级飙升，但实际上都是人们的智能体在跑请求。

所以，我认为这是一个全新的世界，你现在只看到了它冰山一角。但它有很多酷炫的地方。比如在 Proof 和我们其他一些产品里，当有人遇到问题时，他们不会给客服发邮件。他们的智能体会直接发送一份漏洞报告（Bug Report）。

智能体写的 Bug 报告比人类写的要好得多。里面包含了：“这是我具体的操作，这是精确的复现步骤，由于 Proof 是开源的，这是我认为代码库中出问题的地方。”然后我们收到这些，它变成一个 GitHub Issue，我们就可以直接派一个智能体去修复它。虽然不能解决所有问题，但这比以前好太多了。

你可以看到这种极其快速的闭环反馈正在闪烁光芒：我遇到了一个小摩擦、想要一个小功能或发现了一个 Bug，我的智能体直接跑去和该公司的智能体对话，然后公司的智能体直接把问题修复了。这简直酷毙了。

Lenny Rachitsky： 所以，现在很多人都在转向 CLI 并试图在终端里工作。你的预测中有一部分是，人们会从这种方式中转变回来，回到与智能体在图形用户界面（GUI）中并肩工作的 UX 模式中吗？

Dan Shipper： 是的，CLI 的时代结束了。我们相当于“速通”了 CLI 时代。它存在的时候挺美好的，但显然它快结束了。并不是说 CLI 会完全消失，显然它过去三五十年都在，以后也还会存在。在 Claude Code 大火的时候，有人觉得它成功的秘诀在于它是一个 CLI。我不这么认为。

当你进入一个真正的 GUI 后，你会意识到，我们发明 GUI 是有原因的。在 GUI 里就是更舒服。而且你可以在 GUI 中获得所有相同的好处，尤其是在非程序员的工作中。我敢估计，在 Every 内部，大多数技术人员都已经不再将 CLI 作为他们的主要工作界面了。很多程序员偶尔还会切过去用一下，但绝大多数时候，他们在用 Codex、Claude Code 或 Cursor。

Lenny Rachitsky： 太棒了。我想把这一点说清楚。回到这个预测的宏观视角，你预见了两种工作模式。一种是公司内部的超级智能体，你最可能通过 Slack 与它交流，它可以去执行任务和回答问题。另一种是在你的电脑上运行 Codex 或 Claude Code，通常你在电脑上完成的所有工作，现在都将存在于 Codex 或 Claude Code（或者某个我们还不知道的第三方平台）之中，你会使用这些工具内部的浏览器来运行应用。

Dan Shipper： 是的，这听起来可能没那么震撼，但这确实是工作方式的一个巨大改变。我们目前并没有在 Slack 中频繁交流的 AI，目前也并没有主要在 Codex 或 Claude Code 中工作。所以这实际上是一个相当大的转变。

两个智能体比一个强

Lenny Rachitsky： 顺着这个思路，在我们进入下一个预测之前，还有什么要补充的吗？

Dan Shipper： 有几点。我绝对不是“单一智能体至上论者”。我真的认为我们会使用很多不同的智能体，这对我来说很明显。而且我坚信“两个智能体比一个强”。

Lenny Rachitsky： 能举个好例子吗？

Dan Shipper： 当我让 Codex 与另一个智能体互动时，它可以比我自己手动打字提供多得多的关于我以及我的需求的上下文。它可以在后台进行反复的沟通，如果让我直接向一个智能体表达这些，会花很长时间。当你假设你的用户都在使用 Codex 或 Co-work 作为他们访问你应用的基础方式时，你会获得这种巨大的加速效应。

举个简单的例子。我们有一个托管的 Open Claw 产品，之前一直处于候补名单状态。我们甚至不得不向用户收取定金，因为我们开始让人们从候补名单中进入使用。Open Claw 是一个非常难搞的智能体框架，它迭代得太快了。如果你是一个平台，当东西坏了的时候你很难修复它。

但在那个过程中我们学到了一件事：假设你正在构建一个智能体产品或任何新的软件体验，你通常会认为，要设置一个智能体，你需要建立一个网页界面或一个 Slack 工作流，询问用户：“你是谁？你打算用它做什么？你梦想中的理想结果是什么？”就像入职清单上的那些问题。

但如果相反，你设定一条硬性规定：我们只服务于使用 Codex 或 Co-work 的用户。 发生的事情就是，你只需将一个提示词粘贴到 Codex 中。Codex 就会去与你的应用对话（这个应用可以只是一个常规服务器，也可以是它自己的智能体）。由于 Codex 掌握了关于你的极其丰富的信息，它可以直接把这些信息抛过去：“这是我一直在和 Dan 处理的所有事情；这是他可能想使用这个应用的所有方式。”然后应用给出一个极其定制化的体验反馈回来。

并且对于像智能体这样的技术产品，当出现问题时，我只需告诉 Codex：“去修好它。”Codex 就会去和应用对话，帮我弄清楚到底出了什么状况。所以我认为，当你假设每个人都有智能体，并且这些智能体在以这种极其神奇和重要的方式相互对话时，整个产品范式就开始发生改变了。

为什么 Dan 看好 SaaS 股票

Lenny Rachitsky： 在开始下一个部分之前，我还有几点想再深入探讨一下，因为可以聊的太多了。你刚才提到，在使用 SaaS 工具时，可以使用模型公司的 Token（代币）。多讲讲这点，因为这可能会彻底改变未来 SaaS 公司的商业模式。

Dan Shipper： 我认为这实际上可能会拯救他们的利润率。因为现在所有这些 SaaS 公司都在争先恐后地在自己的产品里添加智能体，并认为：“这个内置的智能体会成为人们与我的产品互动的主要方式。”但这显然会消耗大量的 Token，成本高昂。

实际上，一旦我把 Codex 或 Co-work 作为我的主要工作界面，我依然需要使用 SaaS。所以这是另一个很好的预测：我现在就会去买入 SaaS 股票。 我觉得“SaaS 末日论”结束了，SaaS 股票在未来几年内将大幅上涨。（这不是投资建议，但如果是我的话，我会买 SaaS 股票。）

这能拯救 SaaS 的利润率，因为你现在的思维方式不再是“我必须把 AI 强行塞进我的产品里支付算力成本”，而是“我必须打造一款人类和 AI 都愿意共同协作的软件”。这很难，但一旦你构建好了，这比你假设用户全都在消耗你的 Token 要便宜得多。

这是一门好生意。我之所以如此看好 SaaS，部分原因是我们内部每个人都有了智能体，都在用 Codex 之类的工具，但我们依然为大量的 SaaS 付费，并且我们每年的 SaaS 支出都在同比增加。我们并没有什么鸡毛蒜皮的小事都自己用 AI 靠“直觉编程（Vibe coding）”去写个工具替代它。

智能体的作用是增加了 SaaS 的使用者数量，而不是让 SaaS 消失。 所以我认为 SaaS 公司将会看到其产品需求出现疯狂的激增，因为会有海量的智能体极其高频地使用这些产品。正如我所说，这是一个巨大的基础设施挑战，也面临着很多有趣的定价挑战，但这让我非常看好 SaaS。

Lenny Rachitsky： 我太喜欢这个观点了，哪怕这期节目大家只记住了一点：Dan Shipper 说 SaaS 是 AI 的未来。这简直太反共识了。另外一个有趣的点是，你们公司在过去一年里人数翻倍了。对于一家如此前沿的 AI 公司来说，这不符合大家“AI 取代人力”的预期。谈谈你们在这方面的经验吧。

为什么自动化不会减少人类的工作量

Dan Shipper： 好的，实际上我们依然需要人类。“自动化”是一个谎言。 意思是，每次你自动化了一件事情，为了确保这个自动化运行良好，你都需要在它之上安排一个人类，确保它没出乱子。

几年前我写过一篇题为《分配经济（The Allocation Economy）》的文章，核心观点是人类未来与 AI 合作的方式将更像是一个“经理”。你需要记住的是，经理实际上要花大量时间工作。 大多数经理并没有在沙滩上度假，他们总是在跟员工确认进度，试图弄清楚：“我们怎么把这件事做好？怎么做得更好？进展如何？这个人表现怎么样？”等等。

管理人类和管理模型之间有一些区别，但从根本上说，它依然需要投入大量的时间和注意力。我认为我们在讨论 AI 模型的叙事中忽略了这一点。其中一个原因是，各类基准测试（Benchmarks）让 AI 看起来比它实际情况更加自动化。

我所说的“自主性”有其特定的含义，我尽量把它表达清楚，这有点难描述。但我之所以自己领悟到这一点，是因为我切身感受到了这个悖论：我们拥有了如此多的自动化和 AI，但我的工作量却变得大得多了。

当我自己做了一个内部测试基准时，这个悖论稍微解开了一点。我做了一个叫“高级工程师基准测试”的东西，用来衡量 AI 对比人类高级工程师到底有多强。

事情是这样的：我自己利用业余时间（一边管理着 Every），靠“直觉编程（Vibe coded）”写了刚才提到的那个叫 Proof 的应用。但当我们发布它时，因为代码全是 AI 靠直觉堆砌的，服务器直接就挂了，而且我根本修不好。非常丢脸。产品功能是完整的，我们内部也测试过，但发布后第二天，服务器每十分钟崩一次。大家看着我，我说：“我不知道怎么回事。Codex，你来修。”Codex 说：“我不知道怎么回事。”或者更准确地说，Codex 会说：“我知道怎么回事了，我修好了。”结果它的“修复”导致了四个新的错误。我就这样陷入了死循环，整晚没睡。我敲代码敲得太狠，连手肘都得了滑囊炎。

所以教训就是：得了“直觉编程肘”。

总之，我后来找了两位不同的人类高级工程师，让他们独立修复这个问题。所以我得到了两份重写的代码库。这就意味着，当新模型出来时，我只需要给新模型一个提示词：“这是一堆直觉编程搞出来的垃圾代码。如果你想从第一性原理出发重写它，你会怎么写？去干吧。”

在 GPT 5.5 出来之前的所有模型，在这个测试中只能拿到 30 分（满分 100 分）。而人类高级工程师能拿到接近 90 分。差距非常大。然后我测试了 GPT 5.5，它拿了大约 62 分。

你要知道，这 62 分是在 GPT 5.5 使用 Opus 4.7 生成的计划下达到的（Opus 4.7 的规划能力非常好）。GPT 5.5 是目前唯一一个具备足够的主观能动性和自信心，敢于直接把旧代码全部铲掉，真正从第一性原理开始重写的模型。其他编程模型总是试图在边缘缝缝补补，它们会觉得：“哦，这是个大工程，我还是打个小补丁吧。”你只能无奈地说：“不，我明确告诉过你不要这么做。”

所以 GPT 5.5 让分数跃升了 30 分，达到了 60 分。显而易见，再过一年或更短的时间，它就能达到人类高级工程师的水平。这会在你脑海中描绘出一幅图景，尤其是考虑到我是如何给这个基准测试命名的。

但我要告诉你的是，当我们真的到了那一步时，我会非常轻易地修改这个基准测试，把当前模型的分数瞬间“清零”。

例如，我给模型的提示词是：“这是一堆垃圾代码，请从第一性原理重写它。”这听起来好像不需要什么技巧或思考，但实际上，我花了很长时间才摸索出这个既不剧透答案、又能激发模型能力的提示词。

我最初在生产环境崩溃那个早晨给它的提示词其实是这样的：“昨天我们收到了四五个报错。我要你浏览所有问题，然后制定一个解决所有问题的计划，去执行它。”

我可以打赌，市场上的每一个编程模型——我的预测是，即使在一年后，每一个编程模型仍然会死板地执行这个指令。如果你告诉它：“这里有一堆问题，去修好它。”它们就会傻傻地去试图修复那些问题。

但一个真正的人类高级工程师会怎么做？他们会去看一眼代码库，然后骂一句：“这写的是什么狗屎。这人根本不知道自己在干嘛！”然后他们会跑来跟你说：“我们得把这玩意儿彻底重写，这很难也有风险。我知道你不想听这个，但我们必须这么做。”

如果你主动问模型：“嘿，我们应该重写吗？”它可能确实能做到。但它不会主动、独立地做出这个判断。而且有很多机制（安全和对齐）在阻止它这么做。即使它真的这么做了，人类总会有更高维度的框架问题需要解决。

因此，当我们看待基准测试的进步时，从这个角度思考非常重要：基准测试的分数之所以能提升，是因为我们（人类）已经把问题框定好了，我们能够清晰表达并评分。 但现实中还有大量属于人类的工作，那些工作在被写下来之前是无法评分的。而“思考如何给出提示词”或“把它写下来”这个行为本身，就是你无法衡量的能力。这就意味着，即使基准测试被刷爆了，也不等同于它能完全取代所有高级工程师。这就是为什么即使模型自动化能力越来越强，我依然在招聘工程师。

工作形态将如何改变

Lenny Rachitsky： 好的。那么第二类预测，也就是我们所做工作的形态将如何改变？

Dan Shipper： 一旦你进入这个拥有可以异步委派工作的智能体，并且将 Codex 或 Claude Code 作为主要工作界面的时代，有一件事我们内部经常看到，在那些大型模型公司里也看到了，那就是：公司里的 Pull Request（代码拉取请求）数量会呈火箭式暴涨。

我们会看到做咨询的、做运营的，或者编辑岗位的同事，突然都在提交 PR 页面。这真的很酷，这是一种截然不同的工作形态。这意味着你可以预期公司里很大一部分非技术人员，将开始承担以前只有技术人员才能做的事情。

还有，“我们要删掉什么？”我认为 Anthropic 在这点上做得很好。为了确保不显得臃肿，他们从 Claude Code 里删掉了很多东西。

Dan Shipper： 这是一个大问题。同样的事情也发生在工程师身上。这意味着你实际上需要更多的数据工程师和数据科学家，也意味着你还没有建立起合适的系统或智能体来帮你解决这个问题。

Dan Shipper： 我认为它实际上会让工作变得更好。因为对于数据科学家来说，你不再需要处理所有那些愚蠢琐碎的请求了。有人专门建了个智能体帮你挡掉了这些。你可以专注于更深层次、更难回答的问题。它过滤掉了噪音，让你能集中精力。

哪些职位受 AI 影响最小

Lenny Rachitsky： 确实感觉是这样。

我们会阅读更多 AI 写的文章，并且会喜欢它们

Dan Shipper： 还有最后一件事，我觉得很有意思：我认为我们会阅读越来越多 AI 生成的文档和邮件，而且我们会喜欢这种变化。

我们在代码审查里其实已经这么做了。比如阅读需求计划文档，我绝对不想让工程师手写一份规划文档，那太蠢了。同样的道理，2025 年底我们为 Every 做季度规划时，全都是用 Notion 的智能体完成的。

我对这事的期望是：如果你发给我一份 AI 生成的文档，我觉得棒极了。但如果我们讨论它时，我发现你根本不知道里面写了什么，那就是踩红线了，绝对不允许。

我认为我们对 AI 写作的抗拒心理会逐渐消失。因为只要引导得当，GPT 5.5 这种模型写出来的战略文档，比普通人自己在键盘上瞎敲出来的要好太多了。

Lenny Rachitsky： 大多数人确实很不擅长写战略文档，所以这方面人类的门槛本来就很低。

Dan Shipper： 同样适用于写邮件。我现在的邮件大部分是 GPT 5.5 和 Codex 写的。老实说，我甚至更希望在邮件上标明“这封信来自 GPT 5.5”。前几天我要给一位投资人发邮件，我让 Codex 去发。平常它都会先问我确认一下，但这次它没问就直接发出去了。我当时想：“卧槽！”我赶紧去“已发送”里看，结果发现：“哇，这写得完全就是我会发的内容。”

有时候它确实会有点过于正式，但仔细想想，你大部分的工作邮件其实都是程式化、乏味的。我绝对希望是我来构思邮件“应该表达什么核心意思”，但至于具体的句子怎么组织，我通常不太在乎。作为一个极其重视人类写作的人，我这么说可能有点奇怪。我认为人类作家的写作仍然极其重要，这也是我们出版文章的标准。但我们对办公场景下“AI 写作”的抗拒，真的很可笑。

Lenny Rachitsky： 这个视角很有趣。当人们想到 AI 写作时，总会联想到社交媒体上泛滥的内容。但你的观点是，在内部规划、写文档、发邮件这些事情上，AI 写作完全不可怕。而且人们已经在这么做了，很多时候你甚至更愿意看 AI 写的，因为人类写得真的很差。

Dan Shipper： 对外发布的东西也是一样。我们会发布很多指南，这些指南通常都是 AI 辅助或与 AI 共同创作的，而且它们的设计初衷就是让人类和智能体都能阅读。当你写了一份超长的大部头信息指南时，想要真正应用它，最好的方式就是让你的智能体吃透它，然后当你需要做定价策略时提醒你：“别忘了这份指南，我们一起过一遍。”

智能体能在一秒内读完一万页。所以你负责跟人类讲故事、讲重点，而智能体掌握所有的细节，在你需要的时候随时为你调用。

Lenny Rachitsky： 太棒了。在我们进入最后一个板块之前，还有什么要补充的吗？

Dan Shipper： 没有了。

Lenny Rachitsky： 好的，最后一个板块：在这个我们正在逼近的 AI 未来中，谁会获得成功？或者说，人们现在应该做什么才能在未来一两年内获得成功？

为什么产品经理（PM）将主导 AI 时代

Dan Shipper： 我极其看好产品经理（PM）。

我知道你的听众肯定很爱听这个。让我确信这一点的轶事是：我们内部有个叫 Marcus 的同事，他负责我们的写作应用 Spiral。Marcus 出身是 PM，他之前负责 Axios 的写作产品，带了很大的团队，做到了千万级别的 ARR（年度经常性收入）。

他休了一年假，彻底成了重度 AI 用户。他基本学会了如何非常熟练地使用 Cursor。他属于那种“轻度技术型”的人——他知道什么是数据库迁移，如果必须看代码他也能看懂，但放在一年前，我们绝对不可能雇他来做现在的（开发）工作。

但是现在的编程模型已经足够强大了，他能够将自己仅有的一点技术知识，与他极其敏锐的产品嗅觉、对文案的把控以及对用户的同理心结合起来。

这让他变得非常可怕。他发布产品的速度比团队里几乎任何人都快。他极其关注每一个用户、每一次对话，思考：“这意味着什么？我们如何把它融入到接下来的产品规划中？我们需要修复什么问题？”我觉得他被彻底解放了，因为他再也不需要去组织一整个工程团队来做这些事，他自己直接就能干。

这太令人印象深刻了。这让我非常看好任何深入拥抱 AI 的产品经理。

Lenny Rachitsky： Dan，这简直是天籁之音。你这期节目要让无数听众开心死了。很长一段时间以来我一直这么说：代码构建这部分工作以后会自动替你完成。你需要擅长什么？你需要擅长弄清楚“该做什么产品”、“怎么判断它好不好”、“我们要解决什么问题”。我很高兴看到你已经在实践中验证了这一点。

Dan Shipper： 我深信不疑。

Lenny Rachitsky： 这可能会是我所有播客中评价最高的一期。（笑）PM 们要迎来春天了。这大概是我做过最反共识的一期播客了。

全栈设计师是另一个大赢家

Dan Shipper： 另一类我认为将成为“超级赛亚人”的人群，是我们同样在内部看到的：全栈设计师。

如果你是一个设计师，以前你经常会遇到这种情况：我设计了一个极其精美的交互界面，但工程师嫌麻烦不想做，或者做出来的效果跟我预想的完全不一样。而现在，我看到了太多无论是在我们内部还是外部的设计师，他们突然感到被赋予了力量。

他们满脑子都是让东西变好看、增加有趣交互的想法。由于 AI 直觉编程写出来的东西通常看起来千篇一律的丑陋，设计师可以做出与众不同的东西，而且现在他们自己就能把它造出来。你会看到，他们现在也开始直接提交代码的 Pull Request 了。他们不需要再像以前那样把设计稿交接给别人。

这对公司的运作方式来说不可思议。这也给了这些设计师变得更强、甚至自己去创业的巨大机会，因为他们现在可以直接做出成品了。AI 是这类富有创造力的人的超级武器。

Lenny Rachitsky： 我完全同意。尽管现在有很多 AI 设计工具，但很多时候你一眼就能看出来那是 AI 做的。在那种所有人都在不断批量制造“AI 垃圾代码”的环境里，创意和审美的差异化将变得越来越有价值。很有意思的是，我之前做过就业市场调研，设计师岗位的招聘需求已经停滞一段时间了。所以我在观察这是否会反转成一个“我们需要更多设计师”的大趋势。

Dan Shipper： 这很有意思，我们可以拭目以待。

AI 带来的职场末日不会发生

Dan Shipper： 总体而言，我认为所谓的“AI 职场末日”并不会发生。当然，我们看到很多公司开始进行组织架构调整，这很合理。老实说，很多重组打着 AI 的幌子，实际上是因为之前招聘过度导致公司效益不好，这只是个好借口。

但某些 AI 公司 CEO 鼓吹的那种大规模失业潮，我认为是不会发生的。

根据我目前观察到的模式（虽然我没有完美的预知水晶球），新模型发布本质上做的事情是：它们让昨天的“人类专业技能”变得廉价。 它们吸收了过去所有发生过的数据，让你能极其低廉地将其部署到你需要的场景中。

当这项新能力普及后，突然间大家都能做登录页了，到处都是新做的登录页；大家都会写作了，推特上到处都是 AI 生成的废话。但有趣的是，因为大家用的都是相同的模型，采取的都是最基础的默认用法，所有的东西看起来都一模一样。

所以它就被商品化了，不再具有稀缺价值。此时人类会走进去说：“好吧，我们现在拥有了过去所有这些被固化的过往人类能力，我该如何利用它们去创造新的、有趣的东西？”

从结构上讲，由于模型的运作方式和模型公司必须满足的安全/对齐激励机制，模型永远都会跟在那些正在创造新技能、解决新问题的人类后面跑。这些前沿探索最终也会被整合进模型里，但这反过来又为人类继续向前推进腾出了空间。

就像现在人人似乎都是程序员了。但这并不意味着我们要解雇现有的程序员。因为对程序员的需求反而变大了——你需要工程师来判断：“这全都是垃圾代码，它到底该如何合理地整合进我们的代码库里？”这恰恰是不断刷榜的基准测试所无法体现的。所以要彻底颠覆现在的就业结构，还需要很长的时间。

如何“驾驭模型”以保持竞争力

Lenny Rachitsky： 听众们听到“职场末日不会到来”可能会感到一丝安慰。但为了在未来保住饭碗，你可能必须改变现有的工作方式。你对大家如何避免被裁员有什么建议吗？

Dan Shipper： 是的，这极其重要。你唯一需要做的就是：驾驭模型（Ride the models）。

这意味着，无论你是做什么工作的，都要把模型用起来。我们刚才讨论了 Codex 和 Co-work 正在成为工作的新标准操作系统。你要做的就是去用它们，当新模型发布时，去尝试它们，去思考：“我现在拥有了新能力，我要怎么用它？”而不是出于恐惧选择逃避。逃避这种反应是可以理解的，但如果你顺势而为、驾驭这些模型，它们会以一种不会让你掉队的方式扩展你的能力。你将成为未来工作方式的一部分。很长一段时间内，我们都需要大量能做到这一点的人。

Lenny Rachitsky： 我很喜欢“驾驭模型”这个词。假如一个新的大模型发布了，比如对一个在 Salesforce 工作的 PM 来说，他们具体该怎么做去“驾驭模型”？

Dan Shipper： 有意思的是，很多公司反而限制员工去这么做。比如在 Salesforce，你可能用不到最新的模型，或者审批很慢。所以你可能得在业余时间去摸索。

我最喜欢做的事情，就是用新模型去玩。很多时候我知道旧模型还做不到某些事，但当新模型发布时，我总喜欢把石头重新翻开看看：“现在它能做到了吗？”

所以，驾驭模型并没有一个固定的标准动作，因为它们总是在变。核心在于保持好奇心和玩心，把新模型应用到你真正在乎的事情上——无论是你的工作，还是工作之外的爱好，并不断去重新测试。它现在也许不行，但迟早会行。而你使用它的方式决定了你的价值。

大家总以为 AI 的最前沿在旧金山。我反而不这么认为。我认为 AI 的真正前沿，存在于 AI 与正在做实事的普通人相遇的任何角落。 旧金山的那些人造出了 AI，但他们自己未必知道怎么用它。他们需要看其他人怎么用。

当一个新模型发布时，你其实有机会成为世界上第一批发现它新用途的人。这就像一次地理大发现。比如我们公司虽然在布鲁克林，但我真的觉得我们在应用层面上比旧金山的很多人走得靠前得多，因为我们把它用在了方方面面。如果大家能坚持这么做，你很难被时代淘汰。

Lenny Rachitsky： 这正是当前 AI 最神奇的地方之一：无论你穷还是富，你都能获得最先进的 AI 模型。它不是免费的，所以你需要花一点点钱，但你可以和所有人同步用上最新的东西。唯一的特权阶级可能就是 OpenAI 或 Anthropic 的内部员工了吧。

Dan Shipper： 哈哈是啊，之前参加 Anthropic 的活动，看到他们内部都在用未发布的 Mythos 模型，我当时觉得：“太气人了！”但这确实是真的，如果 AI 是由 IBM 发明的，绝对不会是现在这种普惠的局面。它会被标价一亿美元，只有最顶级的公司才能用，而且用在极其无趣的地方。AI 诞生在美国的硅谷文化中是非常关键的，他们的理念是“要把智能变得比水费还便宜”。这意味着每个人都拥有了这种广泛可用的工具。

Lenny Rachitsky： 说得太对了，这也是为什么他们催生了历史上发展最快、规模最大的公司。硅谷那帮人聪明着呢。

最后的总结与建议

Lenny Rachitsky： 纵观我们的对话，这很有趣。像硬币的两面：一方面，很多东西并没有变。SaaS 会继续存在，工作没有大规模消失，我们还在发邮件，还在用 Slack。另一方面，每个角色的底层逻辑又全变了：工程师不怎么手写代码了，PM 不用手写 PRD 了，设计流程也被颠覆了。

Dan Shipper： 我就是这种感觉！我同时处于两种极端情绪中：既对未来的巨大进步极度兴奋，觉得一切都变了；同时又觉得很多事其实还是老样子，这或许是件好事。

我们对未来的直觉，往往就像中世纪的人对地平线尽头的猜想：那边有喷火龙吗？我们会掉进万丈深渊吗？很多人总是有一种深层的直觉，觉得地平线那边会发生可怕的事情；同时另一拨人又觉得那是乌托邦的乐园。结果当你真正跨过那条线，你会发现：有一些很酷的东西，也有一些不那么酷的东西，然后前方还有另一条地平线。

这就要求我们在未来真正显现之前，不要让脑洞跑偏。有些故事在当下听起来很真实，但事后你会发现它复杂得多。一旦你亲身参与其中，你就会看到真相。

Lenny Rachitsky： 部分原因也是 AI 公司自己非常擅长用“未来潜在的危险”来吓唬我们。我觉得这种公关策略毫无意义，虽然他们可能是发自内心的，但我觉得他们想错了。

在进入快问快答环节之前，给大家几点关于如何在未来一年取得成功的行动建议吧？

Dan Shipper：

  1. 驾驭模型： 在 Codex 或 Co-work 里跑一遍你所有的工作流，看看效果如何。如果公司不让，就自己业余时间试。
  2. 尝试像 Open Claw 这样的开源智能体框架。
  3. 享受乐趣： 不要因为“FOMO（错失恐惧症）”或者害怕丢饭碗去用它。要真正找到 AI 给你的工作带来的愉悦感和不可思议的神奇时刻，这才是长久之计。

Lenny Rachitsky： 没找到痛点就去自己试着解决生活里的小麻烦。经常会有“卧槽，这太酷了”的时刻。Dan，还有什么没涵盖到的吗？

Dan Shipper： 差不多了。我很期待一年后看看我会被打几分，你得监督我。

Lenny Rachitsky： 那么 Dan Shipper，我们进入激动人心的快问快答环节。准备好了吗？ 第一，最常推荐给别人的两三本书？ Dan Shipper：

  • 丘吉尔的《第二次世界大战回忆录》。我最近发现丘吉尔是个非常棒的作家，这是历史与回忆录的结合，非常迷人。

Lenny Rachitsky： 最近发现的超爱用的产品？ Dan Shipper： Codex。我不得不再说一次，它真的太好用了。
