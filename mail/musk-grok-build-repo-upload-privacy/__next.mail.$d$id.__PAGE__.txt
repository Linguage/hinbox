3:Tb5d,<h1>马斯克承诺删库 应对Grok Build整仓上传风波</h1>
<h2>摘要</h2>
<p>AI安全研究者Cereblab披露，xAI旗下命令行工具Grok Build在读取文件时会把内容未经脱敏地送往云端存储，甚至将整个代码仓库打包上传，即使用户明确要求它不要打开任何文件。事件发酵后xAI通过服务端开关停止上传，马斯克承诺彻底删除此前数据，但研究者指出真正起效的并非官方推荐的/privacy命令。</p>
<h2>内容框架与概述</h2>
<p>文章先以研究者报告为切口，还原问题本身：Grok Build 不仅在读文件时上传原文，还会把整个仓库打成 Git bundle 传走，保留数月前已删除的历史密钥。一个只要求回复 OK 且禁止打开文件的测试提示，仍然触发了全仓上传，实证性很强。</p>
<p>接着写事件的公共反应与官方回应。其他用户随后报告了更严重的案例，包括整个用户目录连同 SSH 密钥与密码库被打开上传。xAI 高管与马斯克相继发声，强调零数据保留策略、提供 /privacy 命令，并承诺删除存量数据。</p>
<p>最后是研究者与厂商对补救措施的定性分歧。Cereblab 确认上传已停止，但指出真正起作用的是一个静默的服务端全局开关，与用户是否选择退出无关；把 /privacy 当作解决方案会误导开发者，正确默认值应是关闭。文章由此把个案上升为对工具默认权限与数据保留边界的追问。</p>
<h2>核心概念及解读</h2>
<p><strong>整仓上传</strong>：工具将完整代码仓库及 Git 历史打包传输，而非仅上传回答所需文件，泄露面被显著放大。</p>
<p><strong>零数据保留 ZDR</strong>：企业级隐私选项，开启后不留存代码与痕迹数据，但需用户主动启用而非默认。</p>
<p><strong>/privacy 命令</strong>：按会话生效的保留开关，研究者认为它并非修复本次问题的机制，不应被当作控制手段。</p>
<p><strong>静默全局开关</strong>：服务端下发的 disable_codebase_upload 标志，对所有用户强制生效，才是上传停止的真实原因。</p>
<p><strong>默认即关闭</strong>：安全设计原则，主张隐私与数据外发应默认关闭，而非让开发者每次会话手动退出。</p>
