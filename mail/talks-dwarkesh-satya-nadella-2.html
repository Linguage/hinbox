原文：Satya Nadella — How Microsoft is preparing for AGI

访谈正文

作为本次访谈的一部分，Satya Nadella 让 Dylan Patel（SemiAnalysis 创始人）和我独家抢先一睹他们全新的 Fairwater 2 数据中心。

微软正在建造多个 Fairwater，每一个都拥有数十万块 GB200 和 GB300。在这些相互连接的建筑之间，它们将拥有超过 2 GW 的总容量。仅作参照，即便这些 Fairwater 建筑中的单独一栋，也比目前存在的任何其他 AI 数据中心都更强大。

随后 Satya 回答了一系列问题，涉及微软如何在技术栈的各个层面为 AGI 做准备。

AGI 的商业模式

Dylan Patel：

当你回顾过去所有的技术转型——无论是铁路、互联网，还是可互换零件、工业化、云，所有这些——每一次革命从技术被发现到规模化并渗透整个经济，所需的时间都变得越来越短。许多上过 Dwarkesh 播客的人都认为这是最后一次技术革命或转型，而且这一次非常非常不同。

至少到目前为止，在市场层面，三年内我们已经一路飙升到超大规模云厂商明年将投入 5000 亿美元资本支出，就速度而言，这个规模是此前任何革命都无法比拟的。终局似乎相当不同。你对这件事的框架，似乎和我所称的那种“AI 兄弟”很不一样，他们会说：“AGI 要来了。”我想更深入地理解这一点。

Satya Nadella：

我首先也感到兴奋，我也认同这样一种想法：也许在工业革命之后，这是最重大的事情。我从这个前提出发。但与此同时，我也比较清醒地认识到，这仍然处于早期阶段。我们已经构建了一些非常有用的东西，我们看到了一些很好的特性，这些扩展定律似乎正在起作用。我乐观地认为它们会继续起作用。其中一些确实需要真正的科学突破，但也有很多是工程问题等等。

话虽如此，我也倾向于认为，即便是过去 70 年计算领域发生的一切，也是一场帮助我们前进的进程。我喜欢 Raj Reddy 关于 AI 是什么的一个比喻。他是 CMU 的图灵奖得主。甚至在 AGI 之前，他就有了这个关于 AI 的比喻：它要么应该是守护天使，要么应该是认知放大器。我很喜欢这个说法。这是思考这件事是什么的一种简单方式。归根结底，它的人类效用是什么？它将成为认知放大器和守护天使。如果我这样看待它，我就把它看作一种工具。

但你也可以非常神秘地看待它，说这不仅仅是一种工具。它能做所有这些事情，而在此之前只有人类才能做。但过去许多技术也是如此。很多事只有人类能做，然后我们有了工具来做这些事。

Dwarkesh Patel：

我们不必纠结于这里的定义，但一种思考方式是，也许需要五年、十年、二十年。到了某个时候，最终会有一台机器在生产 Satya 词元，而微软董事会认为 Satya 词元价值很高。

Dylan Patel：

你采访 Satya 浪费了多少这种经济价值？

Dwarkesh Patel：

我可付不起 Satya 词元的 API 费用。不管你怎么称呼它，Satya 词元是一种工具还是智能体，随便吧。现在，如果你的模型成本大约是每百万词元几美元或几美分，那么这里就有巨大的利润扩张空间，因为一百万 Satya 词元价值很高。我的问题是，这部分利润流向哪里，微软参与其中的程度有多大。

Satya Nadella：

从某种意义上说，这又回到了本质上：经济增长图景究竟会是什么样？企业会是什么样？生产率会是什么样？对我来说，这又回到了——如果工业革命创造了……是在扩散 70 年之后，你才开始看到经济增长。这是另一件要记住的事。即便这一次技术扩散得很快，要出现真正的经济增长，它也必须扩散到工作、工作产物和工作流程都必须改变的程度。所以我认为，企业要真正改变所需进行的变革管理，是我们不应低估的一点。

展望未来，人类以及他们产生的词元是否会获得更高的杠杆，无论是未来的 Dwarkesh 词元还是 Dylan 词元？想想技术的量级。没有技术，你能运营 SemiAnalysis 或这档播客吗？绝无可能，以你已经能够达到的规模，绝无可能。

所以问题是，那个规模是什么？它会不会因为某种出现的东西而扩大 10 倍？绝对会。因此，无论你是被拉升到某个收入数字，还是被拉升到某个受众数字，或者别的什么，我认为这就是将要发生的事。关键在于，工业革命花了 70 年、也许是 150 年才发生的事，可能会在 20 年、25 年内发生。如果运气好的话，我很乐意把工业革命 200 年间发生的事压缩到 20 年。

Dylan Patel：

微软历史上也许是世界上最伟大的软件公司，最大的软件即服务公司。你们过去经历过一次转型，那时你们卖的是 Windows 许可证和 Windows 或 Microsoft 的光盘，而现在你们卖的是 365 订阅。

当我们从那一次转型走到你们业务今天所在的位置时，在那之后还有另一次转型正在进行。软件即服务的每用户增量成本极低。有大量研发，有大量客户获取成本。这大概就是为什么，不是微软，而是 SaaS 公司在市场上表现大幅落后，因为 AI 的 COGS 实在太高了，而这完全打破了这些商业模式的运作方式。

作为也许是最伟大的软件即服务公司，你如何把微软转型到这个 COGS 很重要、每用户增量成本也不同的新时代？因为现在你们的收费方式像是：“嘿，Copilot 20 美元。”

Satya Nadella：

这是个很好的问题，因为在某种意义上，就商业模式本身而言，杠杆仍将类似。如果你看从消费者一路开始的模式菜单，会有某种广告单元，会有某种交易，对于制造 AI 设备的人来说会有某种设备毛利。会有消费者和企业订阅，然后还会有消费量。所以我仍然认为这些都是计量表。

正如你所说，什么是订阅？到目前为止，人们喜欢订阅是因为他们可以为之做预算。它们本质上是封装在订阅中的某些消费权利的权益。所以我认为，从某种意义上说，这变成了一个定价决策。你被赋予多少消费权利，如果你看所有编码订阅，大致就是如此，对吧？然后你有专业版、标准版，诸如此类。所以我认为，定价和利润结构就会这样分层。

有趣的是，在微软，对我们来说好消息是我们在所有这些计量表上都有业务。在投资组合层面，我们几乎拥有消费量、订阅，以及所有其他消费者杠杆。我认为时间会告诉我们，这些模式中哪些在哪些类别中说得通。

关于 SaaS 方面，既然你提到了，有一点我想得很多。拿 Office 365 或 Microsoft 365 来说。拥有低 ARPU 是好事，因为这里有个有趣的事。在从服务器到云的转型期间，我们过去常问自己的一个问题是：“天哪，如果我们所做的只是基本上把当时使用我们 Office 许可证和 Office 服务器的同一批用户搬到云上，而我们又有 COGS，这不仅会缩小我们的利润率，而且我们从根本上会变成一家利润更低的公司。”

但实际发生的是，向云的迁移疯狂地扩大了市场。我们在印度卖了几台服务器，卖得不多。而在云上，突然之间印度的每个人也能负担得起按比例购买服务器、购买 IT 成本。事实上，例如我此前没有意识到的最大的事，是人们在 SharePoint 底下购买存储所花的钱。事实上，EMC 最大的业务板块可能就是用于 SharePoint 的存储服务器。所有这一切在云上基本都消失了，因为没有人必须去买。事实上，那是营运资本，也就是说，基本上是现金流流出。所以它大规模地扩大了市场。

所以 AI 这件事也会是这样。如果你拿编码来说，我们几十年来用 GitHub 和 VS Code 构建的东西，突然之间编码助手在一年内就变得那么大。我认为这也会是将会发生的事，也就是市场大规模扩张。

Copilot

Dwarkesh Patel：

有一个问题是，市场会扩张，但那些触及微软的收入部分会扩张吗？Copilot 就是一个例子。如果你看今年早些时候，根据 Dylan 的数据，GitHub Copilot 的收入大约是 5 亿美元左右，而且当时没有接近的竞争对手。而现在，你有 Claude Code、Cursor，以及收入大致相近的 Copilot，大约 10 亿美元。Codex 正在追赶，大约 7 亿到 8 亿美元。所以问题是，在微软能够触及的所有界面中，微软那些相当于 Copilot 的产品有什么优势？

Satya Nadella：

顺便说一句，我很喜欢这张图。

我喜欢这张图有很多原因。一是我们仍然位居榜首。二是这里列出的所有公司都是过去四五年里诞生的公司。对我来说，这是最好的迹象。你有新的竞争对手，新的生存问题。当你说，现在是谁？Claude 要杀了你，Cursor 要杀了你，而不是 Borland。谢天谢地。这意味着我们处在正确的方向上。

就是这样。我们从一无所有走到这个规模，这就是市场扩张。这就像云那类东西。从根本上说，编码和 AI 这个类别可能会成为最大的类别之一。它是软件工厂类别。事实上，它可能比知识工作还大。我想对此保持开放心态。

我们将会面临激烈的竞争。这就是你的观点，而且是个很好的观点。但我很高兴我们利用了我们已有的东西走到了这一步，现在我们必须去竞争。在竞争方面，即便是在我们刚刚结束的上一季度，我们做了季度公告，我想我们的订阅用户从 2000 万增长到了 2600 万。我对我们的订阅增长以及这方面的发展方向感觉良好。

但更有趣的事情是，猜猜所有其他那些生成大量代码的公司的所有代码库都去了哪里？它们去了 GitHub。GitHub 在代码库创建、PR 等一切方面都处于历史最高水平。顺便说一句，从某种意义上说，我们想保持它开放。这意味着我们想拥有这一点。我们不想把它与我们自己的增长混为一谈。有趣的是，我们大约每秒有一个开发者加入 GitHub，我想这是那个统计数据。而且其中 80% 的人直接就进入了某种 GitHub Copilot 工作流，因为那里有。顺便说一句，其中许多东西甚至会使用我们的一些代码审查智能体，这些智能体默认开启，只是因为你可以用。我们会有很多很多结构性的机会来做这件事。我们还要做的事，就是我们用 Git 做过的事。GitHub 的原语，从 Git 开始，到 issue，到 actions，这些都是强大而美好的东西，因为它们基本上都围绕你的代码库构建。我们想扩展这一点。

上周在 GitHub Universe，我们大致就是这么做的。我们说 Agent HQ 是我们说要构建的概念性东西。例如，在这里你有一个叫 Mission Control 的东西。你去 Mission Control，现在我可以发号施令。有时我把它描述为所有这些 AI 智能体的有线电视，因为我会把 Codex、Claude、Cognition 的东西、任何人的智能体、Grok，所有这一切都打包进一个订阅里。所以我得到一个套餐，然后我真的可以去发布一个任务并引导它们，这样它们都会在各自独立的分支中工作。我可以监控它们。我认为那将是最大的创新场所之一，因为现在我想能够使用多个智能体。我想能够消化多个智能体的输出。我想能够继续掌控我的代码库。

如果需要构建某种平视显示器，然后让我能快速引导和分诊编码智能体生成的内容，对我来说，这就在 VS Code、GitHub 以及我们将作为 Mission Control 构建的所有这些新原语之间，配上一个控制平面。可观测性……想想所有将要部署这一切的人。它将需要对哪个智能体在什么时间对哪个代码库做了什么进行一整套可观测性。我觉得那就是机会所在。

归根结底，你的观点很有道理，那就是我们最好保持竞争力并创新。如果我们不这样做，我们就会被推翻。但我喜欢这张图，至少只要我们在顶端，即使有竞争。

Dylan Patel：

这里的关键点大致是，无论谁的编码智能体胜出，GitHub 都会持续增长。但这个市场只会以比如 10%、15%、20% 的速度增长，这远高于 GDP。它是一个很棒的复利增长机器。但这些 AI 编码智能体已经从去年年底的比如 5 亿美元年化收入——当时只有 GitHub Copilot——增长到如今，GitHub Copilot、Claude Code、Cursor、Cognition、Windsurf、Replit、OpenAI Codex 等合计的年化收入……今年第4季度这个数字已经达到 50–60 亿美元的年化收入。这是 10 倍。

当你审视软件智能体的 TAM 时，它是你付给人们的 2 万亿美元工资，还是超出那个范围的东西？因为世界上每家公司现在都将能够更多地开发软件？毫无疑问，微软会从中分得一杯羹。但你在仅仅一年内就从接近 100%，或者肯定远高于 50%，变成了低于 25% 的市场份额。人们能有什么信心认为微软会继续赢下去？

Satya Nadella：

Dylan，这要稍微往回说一点，这里没有什么与生俱来的权利，我们不应该有任何信心，只能说我们应该去创新。从某种意义上说，知道我们拥有的幸运突破是，这个品类将会比我们曾经拥有高份额的任何东西都要大得多。让我这样说吧。你可以说我们在 VS Code 中拥有高份额，我们在 GitHub 的代码库中拥有高份额，那是一个不错的市场。但关键是，即使在一个广阔得多的市场中拥有可观的份额……

你可以说我们在客户端-服务器计算中拥有高份额。我们在超大规模计算中的份额比那低得多。但它是不是一个大得多的业务？大了几个数量级。所以至少这证明了，即使我们的份额地位不如从前那么强，只要我们所竞争的市场正在创造更多价值，微软就还行。而且会有多个赢家。就是这样。

但我接受你的观点，归根结底这一切都意味着你必须变得有竞争力。我每个季度都在关注这一点。这就是为什么我对我们在 Agent HQ 上要做的事情非常乐观，把 GitHub 变成一个所有这些智能体都来的地方。正如我所说，我们会在那里有多次射门机会。它不必是……其中一些家伙可以和我们一起成功，所以不必只有一个赢家、一份订阅。

谁的利润率会扩张最多？

Dwarkesh Patel：

我想聚焦这个问题的原因是，这不仅仅关乎 GitHub，而从根本上关乎 Office 以及微软提供的所有其他软件。关于 AI 如何发展，你可以有一种愿景，即模型将继续被束缚，你将需要这种直接可见的、始终存在的可观测性。

另一种愿景是，随着时间的推移，这些现在做需要两分钟任务的模型，将来会做需要 10 分钟、30 分钟的任务。将来，也许它们会自主地做数天的工作。然后模型公司可能会收取数千美元，也许是为了获得一个真正意义上的同事，它可以使用任何 UI 与人类沟通，并在平台之间迁移。
